# stargazers

## Purpose
The `stargazers` plugin (`✨ Stargazers`, category `github`, index 2) walks every affiliated repository
in `data.user.repositories.nodes`, paginates its full stargazer edge list, and builds two daily time
series over the last `days` days: new stars per day (`increments`) and total stargazer count back-computed
from `data.computed.repositories.stargazers` (`total`). It can render those series as `d3`-based SVG
charts and, as an extra, geocode stargazer profile locations into a world choropleth via the `worldmap/`
subdirectory. Supports `user`, `organization` and `repository`; scope `public_access`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Reads `days`, `charts`, `charts.type`, `worldmap`, `worldmap.sample` and the `worldmap.token` setting. When `days` is 0 it is replaced by the account age in days computed from `data.user.createdAt`. Paginates `queries.stargazers()` per repository, collecting `starredAt` dates and (only when worldmap is on) `node.location`. Builds `increments.dates` as a zero-filled map of the last `days` ISO dates, then walks it backwards subtracting increments to derive `total.dates`. Exposes a hardcoded `months` abbreviation array for templates. Dynamically `import("./worldmap/index.mjs")` only when the worldmap extra is allowed. |
| `metadata.yml` | Inputs `plugin_stargazers`, `plugin_stargazers_days` (default 14, `zero: see description` meaning account registration date), `plugin_stargazers_charts` (default yes), `plugin_stargazers_charts_type` (`classic` div-based, `graph` svg-based, `chartist` deprecated alias of `graph`; extras `metrics.npm.optional.d3`), `plugin_stargazers_worldmap` (extras `metrics.api.google.maps` + `metrics.npm.optional.d3`), `plugin_stargazers_worldmap_token` (type `token`), `plugin_stargazers_worldmap_sample` (default 0 = disabled). |
| `examples.yml` | Three examples: classic charts, `charts_type: graph`, and worldmap with `sample: 200` and `${{ secrets.GOOGLE_MAP_TOKEN }}`. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## Skipped subdirectories
- `queries/` — no AGENTS.md: `setup.mjs` `load.plugin` reads every file in it as a GraphQL query string.
  Contents:
  - `stargazers.graphql` (`query StargazersDefault`) — `repository(name: "$repository", owner: "$login") { stargazers($after first: 100, orderBy: {field: STARRED_AT, direction: ASC}) { edges { starredAt, cursor, $location } } }`. Variables: `$login` (repository owner, not the metrics user), `$repository`, `$after` (whole `after: "<cursor>"` clause or empty), `$location` (injected as the literal fragment `node { location }` when the worldmap is enabled, empty otherwise).

## For AI Agents
### Working In This Directory
- `$location` is a textual on/off switch for a whole GraphQL selection, not a value. Leaving it empty keeps the query cheap when the worldmap is off.
- `$login` in this query is the repository owner taken from `data.user.repositories.nodes[].owner.login`, which is not necessarily the metrics account.
- `total` is derived, not queried: it starts from `data.computed.repositories.stargazers` (the current total) and subtracts each day's increments walking backwards. If that computed field is wrong, the whole total series shifts.
- Charts only render when `charts.type` is `graph` or `chartist` AND `imports.metadata.plugins.stargazers.extras("charts.type", {extras})` allows it. With `classic` the plugin returns `charts: true` and the template draws div bars itself.
- The worldmap needs both the `worldmap` extra allowed and a Google Maps token; `worldmap/index.mjs` throws `Google Maps API token is not set` if the token is missing.
- Large accounts are expensive: the plugin paginates every stargazer of every repository at 100 per page, with no cap.
- Any `metadata.yml` change needs `npm run build` (regenerates `README.md`, `action.yml`, `settings.example.json`, `tests/cases/stargazers.plugin.yml`, `.github/workflows/examples.yml`).

### Testing Requirements
- Test case: `tests/cases/stargazers.plugin.yml` covers all three examples including the worldmap one with `plugin_stargazers_worldmap_token: MOCKED_TOKEN`.
- Mocks: `tests/mocks/api/github/graphql/stargazers.default.mjs` returns 50-100 faker edges with `cursor: "MOCKED_CURSOR"` and a `node.location` city, then returns an empty edge list once the query contains `after: "MOCKED_CURSOR"` so the pagination loop terminates. Google geocoding is mocked in `tests/mocks/index.mjs` by monkey-patching `Gmap.prototype.geocode`.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes`.

### Common Patterns
- Textual GraphQL placeholders used both for pagination (`$after`) and for conditional field selection (`$location`).
- Date bucketing by `date.toISOString().slice(0, 10)` and membership check `date in increments.dates`.
- Charts are generated through `imports.Graph.timeline(points, {low, high, match})` with a `match` callback filtering data points down to the tick dates.
- Optional heavy code is loaded with a dynamic `await import("./worldmap/index.mjs")` so it never runs when the feature is off.

## Dependencies
### Internal

- Rendered by `source/templates/classic/partials/stargazers.ejs` and `source/templates/repository/partials/stargazers.ejs`.

### External
- GitHub GraphQL API (`repository.stargazers`) via `@octokit/graphql`.
- `d3` (regular dependency) for graph charts and the worldmap projection.
