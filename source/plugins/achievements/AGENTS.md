# achievements

## Purpose
Renders a set of ranked "achievements" (Developer, Forker, Contributor, Stargazer, Polyglot, ...) computed
from GitHub account statistics. Each achievement carries a rank letter, a progress ratio toward the next rank,
an inline SVG icon whose `#primary`/`#secondary` placeholders are replaced by rank colors, an unlock date and,
for four of them, a leaderboard percentile built from GitHub search counts. The achievement definitions live in
`list/`; `index.mjs` only orchestrates: it resolves the global totals of GitHub issues, repositories and users,
delegates to `list/users.mjs` or `list/organizations.mjs` depending on `account`, then filters, sorts, decorates
and truncates the resulting list.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Plugin entry point. Defines `rank(x, [c, b, a, s, m])` (maps a value to `X`/`C`/`B`/`A`/`S` plus a progress ratio), `leaderboard({user, type, requirement})` (lazy `top`/`percentile` getters over a search count), and `total({imports, graphql, queries})` (memoized on `total.promise`: tries `queries.achievements.total()` first, then falls back to scraping `https://github.com/search?q=created%3A%3E%3D1970` with puppeteer, retrying up to 4 times and rejecting if `users` or `repositories` stays empty). Sorting is `order[rank] + progress * 0.99` descending, so progress breaks ties within a rank. Secret achievements use rank `$` and only show when `plugin_achievements_secrets` is on. |
| `metadata.yml` | `category: github`, `index: 19`, `supports: user, organization`, `scopes: public_access`. Inputs: `plugin_achievements` (gated by the `metrics.run.puppeteer.scrapping` extras permission), `plugin_achievements_threshold` (`S|A|B|C|X`, default `C`), `plugin_achievements_secrets`, `plugin_achievements_display` (`detailed|compact`), `plugin_achievements_limit`, `plugin_achievements_ignored`, `plugin_achievements_only`. `ignored` and `only` match the title without its rank adjective, lower-cased. |
| `examples.yml` | Two examples (detailed and compact display), both with `test.timeout: 1800000` because the total resolution can fall back to puppeteer. |
| `README.md` | GENERATED by `npm run build`. Never hand-edit. |

Several `nodes {name}` blocks are commented out because they would need extra token scopes.
  - `organizations.graphql` (`AchievementsOrganizations`, `$login`) — the organization equivalent: repositories, forks, most-starred repository, projects, packages, `membersWithRole`, sponsorships as sponsor.
  - `ranking.graphql` (`AchievementsRanking`, `$stars`, `$followers`, `$forks`, `$created`) — four `search` counts (`stars:>n` repositories, `followers:>n` users, `forks:>n` repositories, `repos:>n` users) used as the leaderboard numerator.

  - `metrics.graphql` (`AchievementsMetrics`, no variables) — `viewerHasStarred` on `lowlighter/metrics` plus `viewer.login`, for the secret Infographile achievement.
  - `octocat.graphql` (`AchievementsOctocat`, no variables) — `viewerIsFollowing` on `octocat` plus `viewer.login`, for the secret Octonaut achievement.

## For AI Agents
### Working In This Directory
- Adding or changing an achievement is a `list/` edit, not an `index.mjs` edit. `index.mjs` only changes when the
  ranking, filtering, coloring or total-resolution logic changes.
- Rank thresholds are `[C, B, A, S, max]`; `progress` is the fraction toward the next tier and `max` only exists
  so `S` rank has a denominator. Ranks map to color pairs `S #EB355E/#731237`, `A #B59151/#FFD576`,
  `B #7D6CFF/#B2A8FF`, `C #2088FF/#79B8FF`, `$ #FF48BD/#FF92D8`, `X #7A7A7A/#B0B0B0`, and to prefixes
  `S: Master`, `A: Super`, `B: Great`.
- `threshold: X` is what makes unearned achievements visible; it is what the compact example uses.
- The plugin needs the `metrics.run.puppeteer.scrapping` extras permission on a web instance because
  `total()` may launch puppeteer. On the Action it always has it.
- `unlock` dates come from `new Date(node?.createdAt)`; when the node is missing the formatter output matches
  `/invalid date/i` and `unlock` is set to `null` rather than rendered.
- Two secret achievements (`Verified`, `Explorer`) scrape `https://github.com/<login>.gpg` and
  `https://github.com/stars/<login>/topics` through `imports.axios`. No axios mock matches `github.com`, so
  those two requests hit the real network even in mocked test runs.

### Testing Requirements
- `npm run test-metrics` runs `tests/cases/achievements.plugin.yml` (generated from `examples.yml`) for the
  `classic` and `terminal` templates; `repository` is skipped because `supports:` has no `repository`.
- GraphQL mocks: `tests/mocks/api/github/graphql/achievements.default.mjs`, `achievements.organizations.mjs`,
  `achievements.ranking.mjs`, `achievements.total.mjs`, `achievements.metrics.mjs`, `achievements.octocat.mjs`
  (file name `achievements.default.mjs` is matched against `query AchievementsDefault `).
- REST: `rest.packages.listPackagesForUser` / `listPackagesForOrganization` are not mocked; the calls are wrapped
  in `.catch(() => ({data: []}))` so they degrade to 0.
- Rendered by `source/templates/classic/partials/achievements.ejs` only.

### Common Patterns
- Result shape: `{list: [{prefix, title, text, icon, rank, progress, value, unlock, leaderboard}], display}`.
- The total resolution is memoized on a function property (`total.promise`) so concurrent renders share one
  lookup, and the two strategies are a `for (const method of ["graphql", "browser"])` loop that `continue`s on
  error.
- Filtering order: rank threshold (or `$` when secrets are on) -> `only` allowlist -> `ignored` blocklist via
  `imports.filters.text` -> sort -> decorate -> `slice(0, limit || Infinity)`.
