# steam

## Purpose
The `steam` plugin (`🕹️ Steam`, category `social`, no `index` key) renders a Steam player profile and
game history from the Steam Web API. It reports the owned-game count and total playtime, then for the
`most-played` and `recently-played` sections builds per-game cards with icon, short description, genres,
unlocked achievements and an achievement completion rate. Supports `user` and `organization`, needs no
GitHub scopes, and requires a Steam Web API key plus a numeric SteamID64.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Builds a `urls` map over five endpoints (see External below) and fetches owned games first, summing `playtime_forever / 60` for the total. For each requested game section it maps, filters by `playtime.threshold` and `games.ignored` (app ids compared as strings), sorts by playtime or by `rtime_last_played`, slices to the section limit, then for every surviving game issues three further requests: the achievement schema, the store `appdetails`, and the player achievements. Each of those three is individually wrapped in `try/catch` so one failing game degrades to missing fields instead of failing the plugin. Icons come from `http://media.steampowered.com/steamcommunity/public/images/apps/<appid>/<img_icon_url>.jpg` through `imports.imgb64` at 64x64 (achievement icons at 32x32). The `player` section adds level, avatar, `timecreated` and `personaname`. |
| `metadata.yml` | Inputs `plugin_steam`, `plugin_steam_token` (type `token`, extras `metrics.api.steam`), `plugin_steam_sections` (`player`, `most-played`, `recently-played`, all on by default), `plugin_steam_user` (string SteamID64, `preset: no`), `plugin_steam_games_ignored` (app ids), `plugin_steam_games_limit` (default 1), `plugin_steam_recent_games_limit` (default 1), `plugin_steam_achievements_limit` (default 2), `plugin_steam_playtime_threshold` (hours, default 2). Carries a Steam disclaimer. |
| `examples.yml` | Two examples (`metrics.plugin.steam.svg`, `metrics.plugin.steam.full.svg`) with `plugin_steam_user: "0"`. Both override `prod` to `plugin_steam_token: MOCKED_TOKEN` + `use_mocked_data: yes` with the comment "Using mocked data for privacy reasons", so the published examples are faker data. |

## For AI Agents
### Working In This Directory
- The Steam API key is interpolated directly into the URL query string (`?key=${token}`), which means it can end up in `console.debug` output if anyone logs the URL. The current debug lines deliberately log the game name and id instead.
- `metadata.yml` uses `options:` for `plugin_steam_sections` where every other plugin uses `values:`. `metadata.mjs` reads `values`, so the section list is not validated the way other enum inputs are. Fix by renaming the key if you touch it, but that changes generated `action.yml`.
- `plugin_steam_user` is a string, not a number, because SteamID64 values overflow safe integers.
- `games.ignored` entries are compared with `!_games_ignored.includes(\`${id}\`)`, so they must be app ids and are string-compared.
- Section ordering is driven by an inline object lookup inside the sort comparator, `{"most-played": ..., "recently-played": ...}[section]`, which allocates per comparison. Harmless at these limits.
- Per-game cost is three extra HTTP requests, so raising `games.limit` or `recent.games.limit` multiplies API traffic against both `api.steampowered.com` and `store.steampowered.com`.
- `rate.total` counts achievements in the game schema and `rate.achieved` counts the player's unlocked ones; the returned `achievements` array is truncated to `achievements.limit` *after* that count is taken, so the rate stays correct.

### Testing Requirements
- Test case: `tests/cases/steam.plugin.yml`, both cases with `plugin_steam_token: MOCKED_TOKEN` and `use_mocked_data: yes`.
- Mock: `tests/mocks/api/axios/get/steam.mjs`, which branches on URL and returns a full captured `store.steampowered.com/api/appdetails` payload for app 524220 plus faker-backed responses for the player and game-stats endpoints.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_steam_token=MOCKED_TOKEN`.

### Common Patterns
- One `try/catch` per optional enrichment so partial data still renders, with the failure logged through the standard `metrics/compute/<login>/plugins > steam > ...` debug prefix.
- `Promise.all` over the sliced game list, with the per-game work being itself a sequence of awaited fetches.
- Images normalized to base64 with explicit `{width, height}` so the SVG never depends on a remote host.
