# projects

## Purpose
Displays GitHub projects owned by the account plus any explicitly listed repository projects, with their
progress bars or item previews. It has to support two incompatible GitHub project systems at once: classic
projects (`projects`, which expose a `progress` object) and the newer projects v2 (`projectsV2`, which expose
`items` instead), so every fetch exists in a legacy and a v2 variant and the results are merged into one list.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Runs both account-level queries and prepends the v2 projects, then resolves each `:user/:repo/projects/:id` entry by trying four query/account combinations in turn, then formats dates and progress and applies the limit. |
| `metadata.yml` | `category: github`, `index: 25`, `supports: user, organization, repository`. `scopes: public_access, public_repo, read:project` (the only plugin in this batch needing `read:project`). Inputs: `limit` (0-100, default 4), `repositories`, `descriptions`. |
| `examples.yml` | One example, using `METRICS_TOKEN_WITH_SCOPES` and featuring `lowlighter/metrics/projects/1`. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` `load.plugin` reads every file in it as a GraphQL query string.
  Contents:
  - `user.legacy.graphql` (`query ProjectsUserLegacy`) - `$account(login).projects(last: $limit, states: OPEN,
    orderBy UPDATED_AT DESC)` returning `totalCount` and per node `name`, `body`, `updatedAt` and
    `progress {doneCount, inProgressCount, todoCount, enabled}`. Variables: `$account`, `$login`, `$limit`.
  - `user.graphql` (`query ProjectsUser`) - the v2 equivalent, `projectsV2(last: $limit, orderBy UPDATED_AT DESC)`,
    aliasing `title` to `name` and `shortDescription` to `body`, with `items(first: 4, orderBy POSITION ASC)`
    returning `totalCount` and per item `type`, `isArchived` and `fieldValues(last: 100)` narrowed to
    `... on ProjectV2ItemFieldTextValue { text }`. Variables: `$account`, `$login`, `$limit`.
  - `repository.graphql` (`query ProjectsRepository`) - one v2 project by number under a repository:
    `$account(login: "$user").repository(name: "$repository").projectV2(number: $id)` with the same item shape.
    Variables: `$account`, `$user`, `$repository`, `$id`.
  - `repository.legacy.graphql` (`query ProjectsRepositoryLegacy`) - the classic equivalent,
    `project(number: $id)` with the `progress` block. Same variables.

## For AI Agents
### Working In This Directory
- Account-level fetching is unconditional and always costs two GraphQL calls, one legacy and one v2. The v2
  nodes are `unshift`ed so they sort ahead of classic ones, and `totalCount` is the sum of both.
- `plugin_projects_repositories` entries are validated against `/[-\w]+[/][-\w]+[/]projects[/]\d+/` before use,
  and `limit` is raised to at least their count so explicitly featured projects are never cut.
- Resolving a repository project tries, per account type (`user` then `organization`), projects v2 first and
  then classic, inside `try/catch` blocks that only `console.debug` the failure. Up to four queries may run
  for a single entry, and only an all-four failure throws `Could not load project <user>/<repository>`.
- Featured repository projects get their name rewritten to `<name> (<user>/<repository>)`.
- The progress fields only exist on classic projects. For v2 projects `todo`, `doing` and `done` stay `NaN`,
  `enabled` stays `false`, and `total` is overwritten with `items.totalCount`, so any template change must
  handle both shapes.
- `isArchived` is selected by both v2 queries but never read in `index.mjs`. Archived items currently count
  toward the item preview.
- Item text is the first non-empty `ProjectV2ItemFieldTextValue` on the item, which in practice is the title
  field. Only four items are ever requested.
- Missing token scopes are common here, which is why the error handler inspects `error.errors` for
  `INSUFFICIENT_SCOPES` and reports "Insufficient token scopes".

### Testing Requirements
- `tests/cases/projects.plugin.yml`, via `npm run test-metrics`.
- GraphQL mocks: `tests/mocks/api/github/graphql/projects.user.mjs`, `projects.user.legacy.mjs`,
  `projects.repository.mjs`, `projects.repository.legacy.mjs`. The mock proxy matches on the operation name
  with a trailing space, so `ProjectsRepository` and `ProjectsRepositoryLegacy` do not collide. Renaming an
  operation silently unmocks it, so rename the mock file at the same time.
- Rendered by `source/templates/classic/partials/projects.ejs` and
  `source/templates/repository/partials/projects.ejs`.

### Common Patterns
- Account-polymorphic queries substituting `$account` with `user` or `organization` and destructuring the
  response as `(await graphql(...))[account]`.
- Legacy/v2 pairs of queries distinguished by a `.legacy` suffix in the filename, addressed as
  `queries.projects["user.legacy"]` (bracket syntax is required because of the dot).
- Relative date formatting inline: under one day becomes "less than 1 day ago", under 30 days becomes
  "N days ago", otherwise `new Date(...).toDateString().substring(4)`.
