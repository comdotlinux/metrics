# rss

## Purpose
Fetches an arbitrary RSS or Atom feed and renders its most recent entries as a titled, dated link list. It is
the simplest plugin in the repository: one `parseURL` call, one limit, no GitHub API use and no token, which
is why the shipped example points at the Hacker News feed and passes `token: NOT_NEEDED`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | About 25 lines. Imports `rss-parser` directly at module scope, throws when `source` is empty, calls `new rss().parseURL(source)`, maps each item to `{title, link, date: new Date(isoDate)}`, splices to the limit and returns `{source: <feed title>, description, link, feed}`. |
| `metadata.yml` | `category: social`, `index: 7`, `supports: user, organization, repository`, `scopes: []`. Inputs: `source` (feed URL, no default), `limit` (0-30, default 4, documented as `zero: disable`). |
| `examples.yml` | One example: four items from `https://news.ycombinator.com/rss`. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## For AI Agents
### Working In This Directory
- Note the shadowing in the returned object. The plugin input is the feed URL, but the returned `source` is
  the feed's own `title`, and the returned `link` is the feed's site link. The partial shows the feed title,
  not the URL that was configured.
- `rss-parser` is imported directly (`import rss from "rss-parser"`) instead of going through `imports`. That
  is unusual for this codebase but it is what makes the test mock work, because the mock patches the shared
  `rss.prototype.parseURL`. Keep the direct import if you refactor.
- The `eslint-disable-line new-cap` comment on `new rss()` is required because the package's default export
  is lowercase. Do not drop it.
- `limit` of `0` disables the splice, returning every item the feed provides, which can be large. The
  `zero: disable` key in `metadata.yml` is documentation only, consumed by the README generator.
- `date` is built from the parser's `isoDate` field, which some feeds omit. In that case `new Date(undefined)`
  produces an Invalid Date rather than throwing, so guard before formatting if you change the partial.
- There is no queries directory and no GraphQL involvement at all.

### Testing Requirements
- `tests/cases/rss.plugin.yml`, via `npm run test-metrics`.
- This plugin is mocked differently from every other one. There is no file under `tests/mocks/api/`. Instead
  `tests/mocks/index.mjs` monkey-patches `rss.prototype.parseURL` to return 30 faker items with `title`,
  `link`, `content`, `contentSnippet` and `isoDate`, plus a faker feed `title`, `description` and the
  requested URL as `link`. Any real network request in a mocked run means the direct import was broken.
- Rendered by `source/templates/classic/partials/rss.ejs`,
  `source/templates/markdown/partials/rss.ejs` and `source/templates/repository/partials/rss.ejs`.
  The markdown template renders this plugin, so keep the returned data plain and serializable.

### Common Patterns
- The standard plugin guard and `imports.format.error(error)` wrapper, with a single explicit
  `throw {error: {message: "RSS feed URL is not set"}}` for the missing-input case.

## Dependencies
### Internal
`imports.metadata.plugins.rss` (enabled/inputs), `imports.format.error`.
### External
`rss-parser` (npm), and whatever feed URL the user configures.
