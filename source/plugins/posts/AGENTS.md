# posts

## Purpose
Lists a user's most recent blog articles from one external source. Two sources are implemented, dev.to
through its public REST API and hashnode through its GraphQL endpoint, and both are normalized to the same
`{title, description, date, image, link}` shape so a single partial can render either. No GitHub data is
used, so `scopes` is empty and no token of any kind is required.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | A `switch (source)` with one branch per provider, then shared post formatting: limit, optional cover image conversion, and a `link` back to the author's profile page on the source site. |
| `metadata.yml` | `category: social`, `index: 6`, `supports: user, organization, repository`, `scopes: []`. Inputs: `source` (`dev.to` or `hashnode`, no default so it must be set), `user` (defaults to `.user.login`), `descriptions`, `covers`, `limit` (1-30, default 4). |
| `examples.yml` | Two dev.to examples: bare list, and list with descriptions and cover images. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` `load.plugin` reads every file in it as a GraphQL query string.
  Contents:
  - `hashnode.graphql` (`query PostsHashnode`) - fetches `user(username: "$user").publication.posts(page: 0)`
    returning `slug`, `title`, `brief`, `coverImage` and `dateAdded`. Only variable: `$user`. This query is
    not sent to GitHub. It is read as a string and posted to `api.hashnode.com` as an axios request body.

## For AI Agents
### Working In This Directory
- dev.to: `GET https://dev.to/api/articles?username=<user>&state=fresh`. The username is lowercased first,
  because the dev.to API is case-sensitive. Response fields are remapped `published_at` to `date`,
  `cover_image` to `image`, `url` to `link`.
- hashnode: `POST https://api.hashnode.com` with `{query: queries.posts.hashnode({user})}` and
  `Content-type: application/json`. Article links are rebuilt as `https://hashnode.com/post/<slug>`, since
  the API returns only the slug.
- An unknown `source` throws `Unsupported source "<x>"`. Adding a provider means a new `case`, a new
  `values:` entry in `metadata.yml`, and a mock, and the returned objects must keep the shared five fields.
- `covers` converts the cover image with `imports.imgb64(image, {width: 144, height: -1})`. The `-1` height
  preserves aspect ratio. Without `covers` the raw remote URL is left in place and the partial ignores it.
- `descriptions` and `covers` are passed through to the template rather than acted on beyond the image
  conversion, so the partial decides what is actually drawn.
- `limit` of `0` is impossible here (min is 1), unlike most other list plugins.

### Testing Requirements
- `tests/cases/posts.plugin.yml`, via `npm run test-metrics`.
- Mock: `tests/mocks/api/axios/post/hashnode.mjs` covers the hashnode branch. There is no dev.to mock
  anywhere under `tests/mocks/api/axios/get/`, so the two shipped examples (both `plugin_posts_source: dev.to`)
  really call `dev.to` even under `use_mocked_data`. Add `tests/mocks/api/axios/get/devto.mjs` if you need
  that branch hermetic.
- Rendered by `source/templates/classic/partials/posts.ejs`,
  `source/templates/markdown/partials/posts.ejs` and `source/templates/repository/partials/posts.ejs`.
  The markdown template renders this plugin, so keep the returned data serializable and free of SVG-only
  assumptions.

### Common Patterns
- Provider `switch` with a `default:` branch that throws `{error: {message}}`, then a shared post-processing
  block guarded by `Array.isArray(posts)` and a final `throw {error: {message: "Failed to retrieve posts"}}`
  for the unreachable case.
- GraphQL-over-axios: a `queries/*.graphql` file used as a plain string payload for a non-GitHub API.
