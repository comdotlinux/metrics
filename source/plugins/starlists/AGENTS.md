# starlists

## Purpose
The `starlists` plugin (`💫 Star lists`, category `github`, index 16) displays GitHub star lists, which
have no API. It launches puppeteer, scrapes `https://github.com/<login>?tab=stars` for the list cards,
then paginates each list's page scraping repository name, description, language and star/fork counts,
and can aggregate a per-list language breakdown with computed stacked-bar coordinates. Supports `user`
only, requires no GitHub scopes, and declares the `metrics.run.puppeteer.scrapping` extra.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Launches `imports.puppeteer.launch()`, opens one page and reuses it for every navigation. Extracts lists from `[href^='/stars/<login>/lists']` anchors (name from `h3`, description from `span`, count parsed out of a `div` with `/(?<count>\d+)/`). Filters by `only` (allowlist) or `ignored` (denylist), both compared after `imports.stripemojis` + trim + lowercase, then slices to `limit`. For each list it walks `?page=1..100` scraping `#user-list-repositories > div:not(.paginate-container)` and stops early when `.next_page` is missing or `.next_page.disabled` is present. Language colours are read from the inline `backgroundColor` of `.repo-language-color` and converted from `rgb()` numbers to hex. Closes the browser before returning `{lists, count}` where `count` is the pre-filter list total. |
| `metadata.yml` | Inputs `plugin_starlists` (extras `metrics.run.puppeteer.scrapping`), `plugin_starlists_limit` (1-100, default 2), `plugin_starlists_limit_repositories` (0-100, default 2), `plugin_starlists_languages` (default no), `plugin_starlists_limit_languages` (default 8, `zero: disable`), `plugin_starlists_languages_ignored`, `plugin_starlists_languages_aliases` (e.g. `javascript:JS, typescript:TS`), `plugin_starlists_shuffle_repositories` (default yes), `plugin_starlists_ignored`, `plugin_starlists_only` (both case and emoji insensitive). |

## For AI Agents
### Working In This Directory
- Everything here is DOM scraping against github.com HTML. Selectors like `#user-list-repositories`, `.paginate-container`, `.repo-language-color`, `[itemprop='programmingLanguage']`, `.next_page` and `.f3`/`.f5`/`.py-1` Primer utility classes are the contract. A GitHub markup change breaks this plugin silently by returning empty arrays, not by throwing.
- `plugin_starlists_languages` also changes how much is scraped: the page loop runs `1..100` when languages are on and `1..1` when they are off, so language stats are much slower.
- The repository slice happens after the language aggregation, so `limit.repositories: 0` still yields full language statistics over the whole list (that is exactly what the second example does).
- `languages.aliases` is parsed with `/^[\s\S]+:[\s\S]+$/` per comma-separated entry and keys are lowercased; the alias value is used verbatim as the displayed language name.
- `shuffle.repositories` defaults to yes, so output is non-deterministic between runs by design.
- Names are compared after `imports.stripemojis`, which is why the emoji-prefixed list names in the option examples still match.
- The browser is only closed on the success path. An exception mid-scrape leaves the puppeteer process to be cleaned up by the caller.

### Testing Requirements
- Test case: `tests/cases/starlists.plugin.yml`, two cases each with `timeout: 1800000` (30 minutes).
- There is no mock for this plugin: puppeteer is not proxied by `tests/mocks/index.mjs`, so even with `use_mocked_data: yes` these cases hit the real github.com and depend on the `TC39` and `Awesome` star lists of the test account existing. That is why the timeout is so large and why this is one of the slowest cases in the suite.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_starlists: yes`.

### Common Patterns
- `page.evaluate(fn, arg)` with all DOM work inside the browser context; only plain JSON-serializable objects cross back.
- Manual pagination with a next-page sentinel check rather than a fixed page count.
- Stacked-bar precomputation: each language entry gets `p` (share) and a cumulative `x` offset so the template only has to draw rectangles.
