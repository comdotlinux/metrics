# leetcode

## Purpose
LeetCode plugin: pulls a public LeetCode profile's statistics from `https://leetcode.com/graphql` over plain
`axios.post` and renders solved-problem counts per difficulty, per language and per skill tag, plus recent accepted
submissions. `category: social`, `supports: user`, **`scopes: []`** (no GitHub token needed - its example uses
`token: NOT_NEEDED`), `index: 9`. `metadata.yml` carries a disclaimer that the plugin is not affiliated with LeetCode.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Four sequential `imports.axios.post("https://leetcode.com/graphql", {variables, query})` calls, one per query file. Flattens `languageProblemCount` into `{language, solved}`, flattens the three skill categories into a single sorted list, filters it with `imports.filters.text(name, ignored.skills)` on both tag name and category, slices to `limit.skills`, merges `allQuestionsCount` totals with `submitStatsGlobal.acSubmissionNum` solved counts per difficulty, and maps recent submissions to `{title, date}` (the API returns a Unix timestamp in seconds). |
| `metadata.yml` | `plugin_leetcode`, `_user` (default `.user.login`, `preset: no`), `_sections` (`solved`/`skills`/`recent`, default `solved`), `_limit_skills` (10, `zero: disable`), `_ignored_skills` (array; passing `fundamental`, `intermediate` or `advanced` drops a whole category), `_limit_recent` (2, 1-15). |
| `examples.yml` | One example enabling all three sections with `token: NOT_NEEDED`. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` loads every file there as a GraphQL query string. Unlike the GitHub plugins,
  these are **real GraphQL documents with declared variables**, sent as the `query` field of an axios payload while the
  values travel in a separate `variables` object. They are called with no arguments (`queries.leetcode.languages()`), so
  no textual `$var` substitution happens. Contents:
  - `languages.graphql` (op `Languages`, `$username: String!`) - `matchedUser.languageProblemCount { languageName, problemsSolved }`.
  - `skills.graphql` (op `Skills`, `$username: String!`) - `matchedUser.tagProblemCounts` split into `advanced`, `intermediate` and `fundamental`, each `{tagName, problemsSolved}`.
  - `problems.graphql` (op `Problems`, `$username: String!`) - global `allQuestionsCount {difficulty, count}` plus `matchedUser.problemsSolvedBeatsStats` and `matchedUser.submitStatsGlobal.acSubmissionNum {difficulty, count}`.
  - `recent.graphql` (op `Recent`, `$username: String!`, `$limit: Int!`) - `recentAcSubmissionList {id, title, titleSlug, timestamp}`.

## For AI Agents
### Working In This Directory
- **`problems.graphql` over-fetches**: `problemsSolvedBeatsStats` is requested but `index.mjs` never reads it. Either wire
  it into the result or drop it from the query; do not assume it is used.
- The LeetCode endpoint is unauthenticated and undocumented. Schema drift there breaks this plugin without any repo
  change, so failures usually mean the upstream API moved, not a regression here.
- `imports.filters.text` is applied twice per skill (once on the tag, once on the category), which is what makes
  `ignored_skills: fundamental` remove an entire tier.
- `sections` is passed straight through to the template; `index.mjs` always fetches all four datasets regardless of which
  sections are enabled. Trimming requests would require guarding each block.
- `token` is irrelevant for this plugin but the engine still needs one for the base data unless `base: ""` is used.

### Testing Requirements
- `npx jest --runInBand metrics.test.js -t Leetcode` runs `tests/cases/leetcode.plugin.yml`.
- Mock: `tests/mocks/api/axios/post/leetcode.mjs`. `tests/mocks/index.mjs` hands every axios POST mock module
  `{faker, url, body}` and uses the first one that returns something, so this single file answers all four queries by
  inspecting the request body.
- Template rendering it: `source/templates/classic/partials/leetcode.ejs`.

### Common Patterns
- Third-party HTTP goes through `imports.axios`, never octokit. This is the shape shared with `anilist`, `hashnode` and
  the other `tests/mocks/api/axios/post/*` plugins.
- Each dataset is fetched inside its own block scope with a `console.debug(... > leetcode > querying api (<what>))` line.
- Standard enable guard and `try {} catch (error) { throw imports.format.error(error) }`.

## Dependencies
