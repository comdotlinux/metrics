# traffic

## Purpose
The `traffic` plugin (`🧮 Repositories traffic`, category `github`, index 22) sums the page views and
unique visitors across every affiliated repository over the last 14 days, using the GitHub REST traffic
endpoint. It is the only plugin in this batch that uses `rest` rather than `graphql` or `axios`.
Supports `user`, `organization` and `repository`, and requires the full `repo` scope because traffic data
needs push access to each repository.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Reads `skipped` and appends the shared `data.shared["repositories.skipped"]` list. Builds `{repo, owner}` pairs from `data.user.repositories.nodes`, then fires `rest.repos.getViews({owner, repo})` for each one that passes `imports.filters.repo(\`${owner}/${repo}\`, skipped)`, returning `{}` for skipped repositories. Uses `Promise.allSettled` so a private or inaccessible repository does not abort the whole plugin. If every promise rejected it throws `Insufficient token scopes` when all messages match `/must have push access to repository/i`, otherwise it rethrows the first rejection message; partial rejections are only logged at debug level. Sums `count` and `uniques` over the fulfilled responses and returns `{views}`. |
| `metadata.yml` | Inputs `plugin_traffic` and `plugin_traffic_skipped` (array, newline- or comma-separated, `inherits: repositories_skipped`). `scopes: [repo]`. |
| `examples.yml` | One example producing `metrics.plugin.traffic.svg` with `base: repositories`, overriding `prod` to use `${{ secrets.METRICS_TOKEN_WITH_SCOPES }}`. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- `repo` is a broad scope. The plugin makes that explicit twice: in `metadata.yml` `scopes`, and by translating both the all-rejected push-access case and the HTTP 403 case into the message `Insufficient token scopes` through `imports.format.error(error, {descriptions: {"403": "Insufficient token scopes"}})`.
- `plugin_traffic_skipped` inherits `repositories_skipped`, so the global skip list applies automatically. The plugin also unions in `data.shared["repositories.skipped"]` at runtime; both paths exist and both matter.
- `rest.repos.getViews` returns only a rolling 14-day window. There is no input to widen it, and no pagination.
- Skipped repositories resolve to `{}`, which is then filtered out by `.filter(({data}) => data)` before summation. Do not "simplify" that to a truthiness check on the response object.
- The `base: repositories` in the example matters: without the repositories base query, `data.user.repositories.nodes` is empty and the plugin reports zero views.
- One REST call per repository means this plugin is rate-limit heavy on accounts with many repositories.

### Testing Requirements
- Test case: `tests/cases/traffic.plugin.yml`, one case with `token: MOCKED_TOKEN`, `base: repositories`, `use_mocked_data: yes`.
- Mock: `tests/mocks/api/github/rest/repos/getViews.mjs`. REST mocks mirror the octokit method path as directories, so `rest.repos.getViews` maps to `repos/getViews.mjs`.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_traffic: yes` and `base: repositories`.

### Common Patterns
- `Promise.allSettled` plus an explicit all-rejected check, which is how this repo distinguishes "no permission at all" from "a few private repositories".
- `imports.filters.repo(fullname, skipped)` for the shared owner/repo glob filtering used by several plugins.
- Error enrichment via `imports.format.error(error, {descriptions: {...}})` mapping HTTP status codes to user-facing text.
