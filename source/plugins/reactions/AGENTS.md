# reactions

## Purpose
Aggregates the emoji reactions other people left on the user's recent issue comments, issues, discussions and
discussion comments, and renders them as a ranked emoji list with counts or percentages. All four sources are
fetched with the same single query, parameterized by the GraphQL connection name, and each has its own
independent display limit so an account can weight one source over another.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Loops over four `{type, limit}` pairs, paginates each one backwards, filters reactions by ignored user, then tallies `content` values into a `list` of `{value, percentage, score}` and computes the total. |
| `metadata.yml` | `category: github`, `index: 10`, `supports: user` only, `scopes: public_access`. Inputs: `limit` (default 200), `limit_issues`, `limit_discussions`, `limit_discussions_comments` (each 0-1000, default 100), `days`, `display` (absolute/relative), `details` (count/percentage), `ignored` (inherits `users_ignored`). |
| `examples.yml` | One example: limit 100 with `plugin_reactions_details: percentage`. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

  - `reactions.graphql` (`query ReactionsDefault`) - pages one reaction-bearing connection of a user, returning
    per edge the cursor, `createdAt`, and `reactions(last: 100, orderBy CREATED_AT DESC)` with each reaction's
    `content` and `user.login`. Variables: `$login`, `$type` (substituted with `issueComments`, `issues`,
    `repositoryDiscussionComments` or `repositoryDiscussions`), `$before` (pre-rendered as
    `before: "<cursor>"` or empty). This is the plugin's only query, addressed as `queries.reactions({...})`
    rather than `queries.reactions.<file>({...})`, because the file name matches the plugin name.

## For AI Agents
### Working In This Directory
- Pagination runs backwards: the query uses `last: 50` with a `before:` cursor taken from `edges[0].cursor`,
  which walks from the newest comments toward older ones.
- A source whose limit is `0` is dropped from the loop entirely, so setting `plugin_reactions_limit_discussions: 0`
  is the supported way to skip discussions on tokens that cannot read them.
- Each source is wrapped in its own `try/catch` that only logs. A failure (for example discussions on a
  repository type that has them disabled) degrades to fewer sections instead of failing the whole plugin.
- `ignored` is merged with the shared core list via `ignored.push(...data.shared["users.ignored"])`, populated
  by `source/plugins/base/index.mjs`, and applied with `imports.filters.text(user.login, ignored)`.
- Read the `days` filter carefully before changing it. It keeps comments whose `created` date is *before*
  `Date.now() - days * 86400000`, that is, comments older than the cutoff. The input is documented as
  "Comments maximum age" and defaults to `0`, at which point the predicate is effectively always true.
  The `zero: disable` key in `metadata.yml` is documentation only, consumed by the README generator
  (`source/app/metrics/metadata.mjs`), not by any runtime branch.
- `display` only changes the `score` denominator: `absolute` divides by the total reaction count, `relative`
  divides by the highest single reaction count, which makes the bars fill the width.
- `q["config.twemoji"]` is passed straight through in the returned object so the partial can swap native
  emoji for Twemoji images.

### Common Patterns
- One parameterized query file reused for several GraphQL connections through textual `$type` substitution.
- Per-source `try/catch` with `console.debug` so partial data still renders, rather than a single
  plugin-level failure.
