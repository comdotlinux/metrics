# notable

## Purpose
Lists repositories the user has contributed to but does not own, rendered as owner badges. It paginates
`repositoriesContributedTo` over the GraphQL API, filters by owner account type and by a GitHub-search-like
query string, and aggregates results per organization (or per repository handle when
`plugin_notable_repositories` is set). An optional indepth mode spends many more API calls to work out how
much of each repository the user actually wrote, and whether they are a maintainer.

|------|-------------|

| `examples.yml` | Two examples: plain contributions, and indepth with per-repository handles. Both need a real `METRICS_TOKEN`. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` `load.plugin` reads every file in it as a GraphQL query string, so a
  `.md` file would be registered as `queries.notable["AGENTS.md"]`. Contents:
  - `contributions.graphql` (`query NotableContributions`) - pages `user.repositoriesContributedTo` ordered by
    stargazers descending, returning per edge the cursor plus `isInOrganization`, `owner.login`,
    `owner.avatarUrl`, `nameWithOwner` and the `watchers`/`forks`/`stargazers`/`issues`/`pullRequests` counts.
    Variables: `$login`, `$after` (pre-rendered as `after: "<cursor>"` or empty), `$repositories` (page size,
    from `data.shared["repositories.batch"]` or 100), `$types` (uppercased comma-joined contribution types),
    `$self` (include own repositories).
  - `issues.graphql` (`query NotableIssues`) - pages the user's issues or pull requests newest first and
    returns only `repository.nameWithOwner` per edge. Variables: `$login`, `$type` (textually substituted with
    `issues` or `pullRequests`, so one file serves both loops), `$after`.
  - `commits.graphql` - anonymous query (no `query <Name>` header) fetching `repository(owner, name)` through a
    `RepoFragment` to read `defaultBranchRef.target.history(first: 0).totalCount`. Variables: `$owner`, `$repo`.

## For AI Agents
### Working In This Directory
- `skipped` is merged with the shared core list: `skipped.push(...data.shared["repositories.skipped"])`.
  `data.shared` is populated by `source/plugins/base/index.mjs`.
- Search-filter fields are whatever you pass to `imports.filters.github`. Base mode supports `name`, `user`,
  `stars`, `watchers`, `forks`. Indepth mode adds a second filtering pass over `handle`, `commits`,
  `commits.user`, `commits.user%` and `maintainer`, and deliberately keeps repositories whose commit stats
  came back empty rather than dropping them.
- Indepth is gated twice: the `indepth` input and `imports.metadata.plugins.notable.extras("indepth", {extras})`.
  Per repository it issues one GraphQL commit-count query plus `rest.repos.listCollaborators` (roles `admin`,
  `maintain`, `write` count as maintainer) and `rest.repos.getContributorsStats`. The collaborators call is
  wrapped in `.catch(() => ({data: []}))` because a token without access is the normal case, not an error.
- Aggregated `stars` for a contribution are `stars` when the user is a maintainer and `percentage * stars`
  otherwise, computed by a getter so the value follows later percentage normalization.
- `commits.graphql` has no named operation, so the mock proxy in `tests/mocks/index.mjs` (which matches on
  `^query <MockName> `) can never intercept it. Indepth runs therefore hit the live GraphQL API even under
  `use_mocked_data`. Give the query a name if you ever need to mock it, and add the matching mock file.
- Known bug to be aware of before touching the indepth counters: both accumulation lines read
  `issues[repositories]` / `pulls[repositories]` (the boolean input) instead of `issues[repository]`, so the
  per-repository issue and pull counts never exceed 1.

### Testing Requirements
- `tests/cases/notable.plugin.yml`, run through `npm run test-metrics` (or the full `npm test`).
- GraphQL mocks: `tests/mocks/api/github/graphql/notable.contributions.mjs` and `notable.issues.mjs`.
- REST mocks: `tests/mocks/api/github/rest/repos/getContributorsStats.mjs`. There is no `listCollaborators`
  mock, so that call falls through to the real octokit client and is swallowed by its `.catch`.
- Rendered by `source/templates/classic/partials/notable.ejs` only.

### Common Patterns
- Backward cursor pagination: read `edges[edges.length - 1].cursor`, loop while `pushed && cursor`, and
  interpolate the cursor as the whole `after: "..."` argument rather than as a bare value.
- Avatars are converted with `imports.imgb64` inside a `Promise.all` before aggregation.
