# stackoverflow

## Purpose
The `stackoverflow` plugin (`🗨️ Stack Overflow`, category `social`, index 3) queries the public
StackExchange API v2.2 for a numeric Stack Overflow user id and renders account statistics (reputation,
badge total, questions, answers, comments, profile views) plus up to four feeds of rendered posts:
top/recent answers and top/recent questions. It supports `user` and `organization`, needs no GitHub
scopes and no API key: it uses the anonymous StackExchange quota.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Builds `api.base = https://api.stackexchange.com/2.2` and `api.user = .../users/<id>`, then hits `?site=stackoverflow&filter=<user filter>` for the profile and `/comments?site=stackoverflow&filter=total` for the comment count. For each requested section it calls `/answers` or `/questions` with `pagesize=<limit>` and either `sort=activity&order=desc` (recent) or `sort=votes&order=desc` (top), then back-fills the counterpart posts by id (`/questions/<ids joined by ;>` for answers, `/answers/<ids>` for questions). Throws `Stack Overflow user id is not set` when `user` is falsy. |
| `index.mjs` (`format` object) | Module-level formatter with a `cached: Map` keyed `a<id>` / `q<id>`. `format.code()` rewrites StackExchange `<!-- language: lang-x -->` snippet markers into fenced code blocks; `format.answer()` / `format.question()` unescape HTML, render markdown via `imports.markdown(..., {codelines})`, format `creation_date * 1000` as a date, and expose lazy `get question()` / `get answer()` accessors that look the counterpart up in `cached`. |
| `metadata.yml` | Inputs `plugin_stackoverflow`, `plugin_stackoverflow_user` (number, `preset: no`), `plugin_stackoverflow_sections` (`answers-top`, `answers-recent`, `questions-top`, `questions-recent`; default `answers-top, questions-recent`), `plugin_stackoverflow_limit` (1-30, default 2), `plugin_stackoverflow_lines` (default 4, `zero: disable`), `plugin_stackoverflow_lines_snippet` (default 2). Carries a `disclaimer` about not being affiliated with Stack Overflow. |
| `examples.yml` | One example producing `metrics.plugin.stackoverflow.svg` with `plugin_stackoverflow_user: 1`, `token: NOT_NEEDED`. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- There is no `queries/` directory; everything goes through `imports.axios.get`.
- The three hardcoded StackExchange `filter=` strings (`filters.user`, `filters.answer`, `filters.question`) are opaque server-side field selectors generated on api.stackexchange.com. Adding a field to the returned payload means regenerating the filter there, not editing the URL.
- `plugin_stackoverflow_user` is a numeric user id, not a display name. `token: NOT_NEEDED` in examples because no GitHub token is used by this plugin, only the shared metrics run.
- `format.cached` is module-level and never cleared, so it persists across plugin runs in a long-lived web instance. The lazy `question` / `answer` getters rely on that, so do not make it per-invocation without rewiring the getters.
- `lines` is returned to the template as `result.lines` and applied at render time; `lines.snippet` (`codelines`) is applied here when calling `imports.markdown`.
- The anonymous StackExchange quota is 300 requests per IP per day (`quota_max` in the response). Each section costs two requests, so raising `limit` is cheap but adding sections is not.

### Testing Requirements
- Test case: `tests/cases/stackoverflow.plugin.yml`, generated from `examples.yml`.
- Mock: `tests/mocks/api/axios/get/stackoverflow.mjs` matches `^https://api.stackexchange.com/2.2...` and branches on the URL shape (`users/<id>/?site=stackoverflow`, `?site=stackoverflow&filter=total`, answers, questions) with faker data.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_stackoverflow_user` set.

### Common Patterns
- Sections are turned into work by filtering a small descriptor array: `[{key: "answers-recent", sort: ...}, ...].filter(({key}) => sections.includes(key))`.
- Related-post back-fill relies on `format.cached` side effects: the second fetch is awaited purely to populate the cache, its return value is discarded.
- Post bodies come from `body_markdown`, are `imports.htmlunescape`d, passed through `format.code`, then through `imports.markdown`.
