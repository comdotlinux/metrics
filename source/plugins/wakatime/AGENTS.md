# wakatime

## Purpose
The `wakatime` plugin (`⏰ WakaTime`, category `social`, index 8) pulls coding-time statistics from the
WakaTime stats API and renders total and daily-average coding time plus ranked breakdowns of projects,
languages, editors and operating systems, each optionally as a graph. The base URL is configurable so it
also works against a self-hosted `wakapi` instance. Supports `user` only, needs no GitHub scopes, and
requires a WakaTime API key.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Maps `days` through `{7: last_7_days, 30: last_30_days, 180: last_6_months, 365: last_year}` (defaulting to `last_7_days`) and calls `GET <url>/api/v1/users/<user>/stats/<range>?api_key=<token>`. Converts each of `projects`, `languages`, `operating_systems` and `editors` into `{name, percent: percent / 100, total: total_seconds}`, sorts by descending percent and slices to `limit`; languages are additionally filtered through `imports.filters.text(name, _ignored)`. `time.total` and `time.daily` are seconds converted to hours, reading the `*_including_other_language` variants when `languages.other` is set. A `limit` of 0 becomes `undefined` via `void limit` so the slices become unbounded. |
| `index.mjs` (`pickOnlyGitHubPublicRepos`) | Module-level helper used when `repositories.visibility` is `public`. Walks the sorted project list and issues `axios.head(https://github.com/<login>/<project.name>)` per project, keeping only those that respond, stopping once `limit` entries are collected. Returns `undefined` when nothing matched. |
| `metadata.yml` | Inputs `plugin_wakatime`, `plugin_wakatime_token` (type `token`), `plugin_wakatime_url` (default `https://wakatime.com`, documented for wakapi), `plugin_wakatime_user` (default `current`, `preset: no`), `plugin_wakatime_sections` (`time`, `projects`, `projects-graphs`, `languages`, `languages-graphs`, `editors`, `editors-graphs`, `os`, `os-graphs`), `plugin_wakatime_days` (string enum `7`/`30`/`180`/`365`), `plugin_wakatime_limit` (default 5, `zero: disable`), `plugin_wakatime_languages_other`, `plugin_wakatime_languages_ignored`, `plugin_wakatime_repositories_visibility` (`public` or `all`, default `all`). Carries a WakaTime disclaimer. |
| `examples.yml` | One example producing `metrics.plugin.wakatime.svg`, overriding `prod` to `plugin_wakatime_token: MOCKED_TOKEN` + `use_mocked_data: yes` with the comment "Using mocked data because I don't really use WakaTime". |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- The API key goes in the query string (`?api_key=<token>`), not a header. Never log the built URL.
- `sections` is passed straight through to the template and is not used to skip any fetch; the single stats call always returns everything, so adding or removing sections costs nothing at the API level.
- `days` is a string enum, and any value outside the four mapped keys silently falls back to `last_7_days`.
- `repositories.visibility: public` turns one API call into one plus N HEAD requests against github.com, one per project, until `limit` matches are found. On accounts whose WakaTime project names do not match repository names this walks the whole list and returns `undefined`, which templates must treat as "no projects".
- `if (!limit) limit = void limit` is how `zero: disable` is implemented here: `void limit` evaluates to `undefined`, and `Array.slice(0, undefined)` keeps everything.
- The plugin reads `stats.projects`, `stats.languages`, `stats.operating_systems` and `stats.editors` with optional chaining, so a wakapi instance that omits a section yields `undefined` rather than an error.

### Testing Requirements
- Test case: `tests/cases/wakatime.plugin.yml`, generated from `examples.yml`.
- Mock: `tests/mocks/api/axios/get/wakatime.mjs` matches `^https://wakatime.com/api/v1/users/.../stats/...` and only responds when the URL contains `api_key=MOCKED_TOKEN`. It generates 4 to 6 faker entries per section with percentages that sum to 100 and a `digital` getter.
- Note the mock's regex is pinned to `wakatime.com`, so a test exercising a custom `plugin_wakatime_url` would not be mocked.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_wakatime_token=MOCKED_TOKEN`.

### Common Patterns
- Percentages normalized to 0..1 in the plugin so every template renders bars the same way.
- A module-level async helper below the default export, the same shape as the `format` helper in the `stackoverflow` plugin.
- `imports.filters.text(name, ignored)` for the shared case-insensitive ignore-list matching used across plugins.

## Dependencies
### Internal
- `imports.metadata.plugins.wakatime` for `enabled()` / `inputs()`.
- `imports.axios`, `imports.filters.text`, `imports.format.error` from `source/app/metrics/utils.mjs`.
- Rendered by `source/templates/classic/partials/wakatime.ejs` (classic template only).

### External
- WakaTime stats API `GET /api/v1/users/<user>/stats/<range>` (see https://wakatime.com/developers#stats), or a compatible `wakapi` instance.
- `https://github.com/<login>/<project>` HEAD probes when `repositories.visibility` is `public`.
- `axios` (via `imports.axios`).
