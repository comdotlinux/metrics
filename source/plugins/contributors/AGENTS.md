# contributors

## Purpose
Lists the contributors of a single repository between two git references, with their commit counts, the pull
request numbers referenced in their commit messages, and optionally a breakdown by contribution category
(documentation, code, other, ...) derived from the file paths each contributor touched. It is a
repository-only plugin: `supports:` is just `repository`, so it needs the `repository` template and reads
`data.repo` (owner and name) rather than `data.user`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Resolves the `head` and `base` refs to commit objects via GraphQL, then pages `rest.repos.listCommits` until it reaches the base commit SHA (or runs out of pages), splices off everything before the head SHA, tallies commits per author login, collects `(#123)` pull request references out of commit messages, and sorts contributors by commit count. The `categories` section clones the repository into a temporary directory with `imports.git`, runs `git --no-pager log --author=<contributor> --regexp-ignore-case --no-merges --name-only` through `imports.spawn`, and matches each touched file against the category globs with `imports.minimatch(file, glob, {nocase: true})`, assigning each file to the first matching category. |
| `metadata.yml` | `category: github`, `index: 8`, `supports: repository`, `scopes: public_access`. Inputs: `plugin_contributors`, `plugin_contributors_base` (default empty), `plugin_contributors_head` (default `master`), `plugin_contributors_ignored` (`inherits: users_ignored`), `plugin_contributors_contributions`, `plugin_contributors_sections` (`contributors`, `categories`), `plugin_contributors_categories` (a JSON map of category name to file globs, gated by the `metrics.run.tempdir` and `metrics.run.git` extras permissions). |
| `examples.yml` | Two examples, both with `template: repository` and `repo: metrics`: contributions count, and a categories breakdown mapping plugins/templates, documentation and other code. |
| `README.md` | GENERATED by `npm run build`. Never hand-edit. |

## Skipped subdirectories
- `queries/` — no AGENTS.md: `setup.mjs` loads every file in it as a GraphQL query. Contents:
  - `commit.graphql` (`ContributorsCommit`, `$owner`, `$repo`, `$expression`) — resolves a ref expression
    (commit SHA, tag or branch) to `oid`, `abbreviatedOid`, `messageHeadline` and `committedDate` through
    `repository.object(expression:)` with an inline `... on Commit` fragment. Called twice, once for `head` and
    once for `base`.

## For AI Agents
### Working In This Directory
- The commit range is resolved by SHA position in the REST listing, not by a compare API call: pagination stops
  at the page containing `ref.base.oid`, and `commits.splice(0, indexOf(ref.head.oid))` removes anything newer
  than head. An empty `base` therefore means "walk the whole history", which is the default and is slow on large
  repositories.
- The default `head` is the literal string `master`. On a repository whose default branch is `main` the head
  resolution returns `null`, `indexOf` returns `-1`, `Math.max(0, -1)` is `0`, and the plugin silently falls
  back to the full listing. Set `plugin_contributors_head` explicitly when testing against such repositories.
- The categories section needs the `metrics.run.tempdir` and `metrics.run.git` extras permissions and performs a
  full `git clone` into `os.tmpdir()`. Failures are swallowed (logged, then the `finally` block removes the temp
  directory), so an empty `categories` map in the output usually means the clone or the `git log` failed, not
  that no files matched.
- Category assignment is first-match-wins per file (`continue filesloop`), so glob order inside
  `plugin_contributors_categories` matters and a catch-all like `"*"` must be declared last.
- `ignored` is the plugin input concatenated with `data.shared["users.ignored"]`, and it is checked against both
  the commit author login and the commit author email with `imports.filters.text`.
- Avatars go through `imports.imgb64` once per contributor, so a repository with many contributors produces a
  large SVG; that is expected, not a bug to optimize away silently.
- There is a shadowing quirk in the tally loop: the destructured `login` of each commit author shadows the outer
  `login` of the rendered account inside that loop, including in its debug messages.

### Testing Requirements
- `npm run test-metrics` runs `tests/cases/contributors.plugin.yml`. Both cases force `template: repository`
  and `repo: metrics`; the `classic` and `terminal` templates are skipped because only
  `source/templates/repository/partials/contributors.ejs` exists.
- Mocks: `tests/mocks/api/github/graphql/contributors.commit.mjs` (matched against `query ContributorsCommit `)
  and `tests/mocks/api/github/rest/repos/listCommits.mjs`. The `categories` path runs a real `git clone` and is
  not mocked, so that example depends on network access when run for real.
- Rendered by `source/templates/repository/partials/contributors.ejs`.

### Common Patterns
- Result shape: `{head, base, ref: {head, base}, list: {<login>: {avatar, contributions, pr: [...]}}, categories: {<category>: Set}, contributions, sections}`.
- Pull request numbers are scraped from commit messages with `message.match(/(?<=[(])#\d+(?=[)])/g)` and then
  de-duplicated through a `Set`.
- The temporary-directory block is `try / catch (log only) / finally (rm -rf)`, so it can never leave the clone
  behind or fail the whole plugin.
