# anilist

## Purpose
Pulls an [AniList](https://anilist.co) profile into metrics: watch and reading statistics, the current
watching/reading lists, favorite animes and mangas, and favorite characters. AniList is itself a GraphQL API,
but it is not GitHub's, so the plugin posts the queries from `queries/` to `https://graphql.anilist.co` with
`imports.axios.post` (real GraphQL `$variables` are sent in the request body here, unlike the textual `$var`
substitution used for GitHub queries). Cover images and character portraits are inlined with
`imports.imgb64`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Fetches user statistics, then optionally the medias lists, favorite medias and favorite characters depending on `sections`. Contains `format({media, imports})` which flattens an AniList media entry into `{name, type, status, release, genres, progress, description, scores: {user, community}, released, artwork}` (`released` is `episodes` for anime and `chapters` for manga, and `<br>` tags are stripped from descriptions), and `retry({login, imports, error})` which waits `retry-after + 5` seconds and retries once on an HTTP 429, rethrowing anything else. |
| `metadata.yml` | `category: social`, `index: 4`, `supports: user, organization`, `scopes: []` (no GitHub token scope needed). Inputs: `plugin_anilist` (gated by the `metrics.run.puppeteer.scrapping` extras permission), `plugin_anilist_user` (defaults to `.user.login`), `plugin_anilist_medias` (`anime`, `manga`), `plugin_anilist_sections` (`favorites`, `watching`, `reading`, `characters`), `plugin_anilist_limit` (medias, default 2), `plugin_anilist_limit_characters` (default 22), `plugin_anilist_shuffle`. Carries a `disclaimer:` (no affiliation with AniList). |
| `examples.yml` | Three examples: anime watch list, manga reading list, favorite characters. |
| `README.md` | GENERATED by `npm run build`. Never hand-edit. |

## Skipped subdirectories
- `queries/` — no AGENTS.md: `setup.mjs` loads every file in it as a GraphQL query. These are AniList queries,
  not GitHub ones. Contents:
  - `statistics.graphql` (`Statistics`, `$name: String`) — user id, name, about, and `statistics.anime`
    (count, minutes watched, episodes watched, top 4 genres) and `statistics.manga` (count, chapters read,
    volumes read, top 4 genres).
  - `medias.graphql` (`Medias`, `$name: String`, `$type: MediaType`) — `MediaListCollection` grouped into named
    lists (Watching, Completed, ...), each entry expanded through the `mediaListEntry` fragment with status,
    progress, score, start/completion dates and the embedded media object.
  - `favorites.graphql` (`Favorites`, `$name: String`, `$page: Int`) — paginated favorite medias; the
    `$type` placeholder is substituted textually by `queries.anilist.favorites({type})` before sending, so it
    becomes the literal field name `anime` or `manga`.
  - `characters.graphql` (`FavoritesCharacters`, `$name: String`, `$page: Int`) — paginated favorite characters
    with `name.full`, `name.native` and `image.medium`.

## For AI Agents
### Working In This Directory
- `favorites.graphql` mixes the two substitution styles on purpose: `$type` is replaced textually by
  `queries.anilist.favorites({type})` while `$name` and `$page` travel as real GraphQL variables in the axios
  body. Renaming either breaks silently.
- Rate limiting is the main failure mode. The statistics and medias blocks use a
  `for (let retried = false; !retried; retried = true)` loop so they retry exactly once; the paginated favorites
  and characters loops call `retry()` and `continue` without advancing the page. A non-429 error propagates to
  the outer `catch` and becomes `imports.format.error(error)`, which turns an axios error into
  `API error: <status> (<message>)`.
- `sections` drives which requests are made at all: `watching`/`reading` trigger the medias lists (one request
  per entry in `medias`), `favorites` triggers the paginated favorites, `characters` triggers the paginated
  characters. The result always has the `lists` keys for every requested media type, even when empty.
- `shuffle` uses `imports.shuffle` (in-place Fisher-Yates) and runs before the `splice(limit)` truncation, so it
  is what makes repeated renders show different entries.
- The `metrics.run.puppeteer.scrapping` extras permission on `plugin_anilist` is a web-instance gate inherited
  from the social-plugin convention; this plugin does not actually launch puppeteer.
- `plugin_anilist_user` defaults to `.user.login`, a special value that `metadata.mjs` substitutes with the
  GitHub login, which is only correct when the two usernames match.

### Testing Requirements
- `npm run test-metrics` runs `tests/cases/anilist.plugin.yml` for `classic` only (no `anilist.ejs` partial
  exists in `terminal` or `repository`, and `supports:` has no `repository`).
- Mock: `tests/mocks/api/axios/post/anilist.mjs`, matched on the URL `https://graphql.anilist.co` and then on
  the query name (`query Statistics `, `query Medias `, `query Favorites `, `query FavoritesCharacters `). It
  returns `coverImage.medium: null` and `image.medium: null`, so `imports.imgb64` is exercised with a null URL.
- Rendered by `source/templates/classic/partials/anilist.ejs`.

### Common Patterns
- Every request is `await imports.axios.post("https://graphql.anilist.co", {variables: {...}, query: queries.anilist.<file>()})`
  and the response is destructured straight down through `{data: {data: {User: {...}}}}`.
- Pagination is a `do { ... } while (next)` loop driven by `pageInfo.hasNextPage`.
- Limits are applied after collection with `array.splice(limit)` guarded by `if (limit > 0)`, so `0` means
  unlimited (documented as `zero: disable`).
