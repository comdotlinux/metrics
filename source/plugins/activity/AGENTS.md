# activity

## Purpose
Turns the GitHub events feed into a render-ready timeline. It pages through the REST events API, filters by
actor, age, visibility, repository and user, then maps each raw GitHub event type onto one of the plugin's own
normalized event shapes (`push`, `issue`, `pr`, `review`, `comment`, `ref/create`, `ref/delete`, `release`,
`wiki`, `fork`, `star`, `member`, `public`). It has no `queries/` directory: everything comes from REST.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | The whole plugin. Switches to repository mode when `q.repo` is set (taking owner/repo from the first entry of `data.user.repositories.nodes`) and then calls `rest.activity.listRepoEvents({owner, repo})`, otherwise `rest.activity.listEventsForAuthenticatedUser({username: login, per_page: 100, page})` for `Math.ceil(load / 100)` pages. The core is a `switch (type)` over the GitHub event types, each branch returning a flat object with `{type, actor, timestamp, repo, ...}`. Markdown bodies go through `imports.markdown(content, {mode: markdown, codelines: 2})`. |
| `metadata.yml` | `category: github`, `index: 21`, `supports: user, organization, repository`, `scopes: public_access`. Inputs: `plugin_activity`, `plugin_activity_limit` (1-1000, default 5), `plugin_activity_load` (100-1000 events, default 300), `plugin_activity_days` (0-365, default 14, `0` disables the age filter), `plugin_activity_visibility` (`public|all`), `plugin_activity_timestamps`, `plugin_activity_skipped` (`inherits: repositories_skipped`), `plugin_activity_ignored` (`inherits: users_ignored`), `plugin_activity_filter` (the 13 event types plus `all`). |
| `examples.yml` | One example filtering on `issue, pr, release, fork, review, ref/create` with `plugin_activity_days: 0`. |
| `README.md` | GENERATED by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- **Adding an event type** means three coordinated edits: a new `case "<GitHubEvent>"` branch in the `switch`,
  the new `type` string added to the `values:` list of `plugin_activity_filter` in `metadata.yml`, and a render
  branch in `source/templates/classic/partials/activity.ejs` (plus `repository/partials/activity.ejs` and
  `markdown/partials/activity.ejs` if it should show there). Then `npm run build`.
- Branches that check `payload.action` deliberately drop the other actions: `CommitCommentEvent`,
  `IssueCommentEvent`, `PullRequestReviewCommentEvent` and `MemberEvent` only keep `created`/`added`,
  `IssuesEvent` keeps `opened|closed|reopened`, `PullRequestEvent` keeps `opened|closed` (and rewrites a merged
  close to `action: "merged"`), `ReleaseEvent` keeps `published`, `WatchEvent` keeps `started`. Unknown types
  return `null` and are dropped.
- Filtering order in `index.mjs`: actor login (skipped entirely for organizations), `created_at` age,
  `visibility`, then per-event `imports.filters.repo(repo, skipped)` and `imports.filters.text(user, ignored)`,
  then the `filter` allowlist, then `slice(0, limit)`. The skipped and ignored lists are the plugin inputs
  concatenated with `data.shared["repositories.skipped"]` and `data.shared["users.ignored"]`.
- **Modern events can arrive without the sub-objects the branches destructure** (upstream PR 1834): a `PushEvent`
  payload may carry no `commits` array, and `CommitCommentEvent`, `IssueCommentEvent`, `IssuesEvent`, `MemberEvent`
  and `PullRequestEvent` payloads may have no `user`/`member`. Hence the `payload.commits ?? []` guard and the
  `if (!payload.<x>?.user) return null` early returns before each destructuring; a new branch that destructures
  `payload` needs the same guard or a single anonymised event crashes the whole plugin.
- `PushEvent` drops commits whose author email is ignored, and when the last commit message starts with
  `Merge branch ` it keeps only that one commit. SHAs are truncated to 7 characters.
- `days: 0` is translated to `Infinity`, which means "no age limit", not "no events".
- The `markdown` setting comes from the per-plugin settings object (the third destructured argument), not from
  `metadata.yml`; the web instance sets it from `settings.json` and it selects `inline` or full markdown
  rendering for event bodies.
- Repository mode calls `listRepoEvents` without pagination parameters, so `plugin_activity_load` effectively
  only controls the user-mode page count.

### Testing Requirements
- `npm run test-metrics` runs `tests/cases/activity.plugin.yml` against `classic`, `terminal` and `repository`
  (the plugin supports `repository`, and `classic`, `markdown` and `repository` all have an `activity.ejs`
  partial; `terminal` has none so it is skipped).
- Mocks: `tests/mocks/api/github/rest/activity/listEventsForAuthenticatedUser.mjs` and
  `tests/mocks/api/github/rest/activity/listRepoEvents.mjs`. They emit one event of each supported type, so a
  new `case` branch needs a matching entry added to those mock files to be covered.
- Rendered by `source/templates/classic/partials/activity.ejs`,
  `source/templates/repository/partials/activity.ejs` and `source/templates/markdown/partials/activity.ejs`.

### Common Patterns
- Result shape: `{timestamps, events: [...]}`; every event carries `type`, `actor`, `timestamp` (a `Date`),
  `repo`, plus type-specific fields.
- The whole mapping is one `await Promise.all(events.map(async ...))` because `imports.markdown` is async.
- Pagination is a `try { for (let page ...) } catch { /* no more page */ }` block, so an API error mid-way keeps
  the events already collected instead of failing the plugin.

## Dependencies
### Internal
- `source/app/metrics/metadata.mjs` (`inputs()`, `enabled()`), `source/app/metrics/utils.mjs`
  (`imports.markdown`, `imports.filters.repo`, `imports.filters.text`, `imports.format.error`),
  `data.shared` from `source/plugins/base/index.mjs`, the three `activity.ejs` partials.

### External
- GitHub REST events API (`rest.activity.listEventsForAuthenticatedUser`, `rest.activity.listRepoEvents`); see
  the GitHub event types documentation referenced in the `plugin_activity_filter` description.
