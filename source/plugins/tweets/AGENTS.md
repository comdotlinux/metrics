# tweets

## Purpose
The `tweets` plugin (`🐤 Latest tweets`, category `social`, index 1) fetches a Twitter profile and its
recent tweets through Twitter API v2 and renders them with mentions, hashtags and links marked up as
spans and anchors, optionally with media attachments and OpenGraph previews of linked pages. Supports
`user` and `organization` and needs no GitHub scopes, but does need a Twitter bearer token.
`metadata.yml` carries a `deprecation` notice: Twitter removed free-tier tweet retrieval, so the plugin
is no longer maintained.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Two authenticated GETs with an `Authorization: Bearer <token>` header: `https://api.twitter.com/2/users/by/username/<user>?user.fields=profile_image_url,verified` for the profile, and `https://api.twitter.com/2/tweets/search/recent?query=from:<user>&tweet.fields=created_at,entities&media.fields=preview_image_url,url,type&expansions=entities.mentions.username,attachments.media_keys` for the timeline. Builds a `media_key -> url` map resolving `photo`/`animated_gif` to `url` and `video` to `preview_image_url`. Truncates to `limit`, then per tweet: collects mentions and a `url -> display_url` map, and when `attachments` is on strips the trailing link out of the text, base64-encodes each media attachment at width 450, and scrapes the last link with `imports.opengraph` to build an image/title/description/website card (falling back to appending the bare URL when no image is available). Text formatting double-escapes through `imports.htmlescape` (first `<`/`>`, then `&`) and wraps mentions in `<span class="mention">`, hashtags in `<span class="hashtag">` using a long Unicode hashtag regex lifted from the Twitter source, newlines into `<br/>`, and URLs into `<a class="link">`. |
| `metadata.yml` | Inputs `plugin_tweets` (extras `metrics.api.twitter.tweets`), `plugin_tweets_token` (type `token`), `plugin_tweets_user` (default `.user.twitter`, `preset: no`), `plugin_tweets_attachments` (default no), `plugin_tweets_limit` (1-10, default 2). Carries both a `disclaimer` and the `deprecation` block linking the Twitter API pricing policy change. |
| `examples.yml` | Two examples (`metrics.plugin.tweets.svg` and `metrics.plugin.tweets.attachments.svg`, both `plugin_tweets_user: github`), each with `prod.skip: true` and `test.skip: true`. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- Deprecated: `tweets/search/recent` is not available on the Twitter free tier any more, so a real run fails at the second request regardless of token. Treat this directory as reference, not as something to extend.
- `plugin_tweets_user` defaults to `.user.twitter`, a metadata path expression resolved by `metadata.mjs` against the GitHub profile's Twitter username field, so the option normally needs no explicit value.
- The link-rewriting regex is built from the tweet's own URL list. When a tweet has no URLs, the code prefixes the pattern with `noop^` to produce a regex that can never match, rather than branching. Do not "clean that up" without replacing it with an explicit guard.
- The double `imports.htmlescape` is deliberate: tags are escaped first so the injected `<span>`/`<a>` markup survives, then only `&` is escaped in the second pass.
- OpenGraph scraping happens inside a `try/catch` that only debug-logs; a slow or hostile linked page degrades the card silently but still costs a network round trip.
- `tweet.attachments` is overwritten in place, moving from Twitter's `{media_keys}` object to an array of `{image}` entries, with the OpenGraph card `unshift`ed in front. Templates must handle `null` (attachments disabled) as well.

### Testing Requirements
- `tests/cases/tweets.plugin.yml` is an empty list (`[]`) because both examples set `test.skip: true`. Nothing in the jest suite runs this plugin.
- A mock does exist: `tests/mocks/api/axios/get/twitter.mjs` matches `^https://api.twitter.com/...` and only responds when `options.headers.Authorization === "Bearer MOCKED_TOKEN"`, covering both the profile and the recent-tweets endpoints with faker data. It is reachable manually even though no test case uses it.
- Manual run: `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_tweets: yes` and `plugin_tweets_token: MOCKED_TOKEN`.

### Common Patterns
- Bearer-token auth passed as the second `imports.axios.get` argument (`{headers: {Authorization: ...}}`), which is also what the mock keys off.
- Twitter API v2 `expansions` flattened into a lookup `Map` before per-tweet processing.
- Chained `String.replace` passes to build inline HTML, each step assuming the previous one already escaped what it needed to.
