# pagespeed

## Purpose
Audits a website with Google's PageSpeed Insights v5 API and renders the Lighthouse category scores, with
optional detailed timing metrics and a final screenshot of the audited page. It touches no GitHub data, so
`scopes` is empty, but it defaults the audited URL to the profile website field (`.user.website`), which is
how it ends up on user and repository templates.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Normalizes the URL, builds a `&category=` list, performs one `imports.axios.get` for scores and a second one for detailed metrics, and attaches a base64 screenshot when asked. Ends with a custom `imports.format.error` description map. |
| `metadata.yml` | `category: social`, `index: 0`, `supports: user, organization, repository`, `scopes: []`. Inputs: `token` (extras `metrics.api.google.pagespeed`), `url` (default `.user.website`), `detailed`, `screenshot`, `pwa`. |
| `examples.yml` | Four examples (succinct, detailed, screenshot, PWA). The PWA one is `prod.skip: true`. All pass `token: NOT_NEEDED` for GitHub and a separate `PAGESPEED_TOKEN`. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## For AI Agents
### Working In This Directory
- Audited categories are hardcoded: `performance`, `accessibility`, `best-practices`, `seo`, plus `pwa` when
  `plugin_pagespeed_pwa` is set. Each score is read from `lighthouseResult.categories[category]`.
- The URL is prefixed with `https://` when it has no scheme. Note that `result.url` is rebuilt from
  `imports.url.parse` as `protocol//host` only, so the displayed URL drops any path or query string while
  the request still audits the full URL.
- `detailed` costs a second full API call, made without the `&category=` filters, and flattens
  `lighthouseResult.audits.metrics.details.items` into `result.metrics` (First Contentful Paint, Speed Index,
  Largest Contentful Paint, Time to Interactive, Total Blocking Time, Cumulative Layout Shift).
- `screenshot` copies `lighthouseResult.audits["final-screenshot"].details.data` verbatim. It is already a
  data URI from the API, so `imports.imgb64` is deliberately not used, and it inflates the SVG considerably.
- The token is optional but rate limiting is aggressive without it. That is why the error handler maps HTTP
  429 to a hint about `plugin_pagespeed_token`, and why the `custom` handler re-surfaces the
  `Lighthouse returned error: <CODE>` string buried in the API error body.
- Token handling follows the repo convention: `imports.metadata.plugins.pagespeed.extras("token", {extras, error: false})`
  blanks the token when the extras gate is not granted, and the query is sent without `&key=`.

### Testing Requirements
- `tests/cases/pagespeed.plugin.yml`, via `npm run test-metrics`.
- Mock: `tests/mocks/api/axios/get/pagespeed.mjs`. It only answers URLs matching
  `v5.runPagespeed.*&key=MOCKED_TOKEN`, so a mocked run that omits `plugin_pagespeed_token: MOCKED_TOKEN`
  falls through to the real Google API. Keep that input in any new test case.
- The mock returns `final-screenshot.details.data` as `null`, so screenshot cases exercise the code path but
  render nothing.
- Rendered by three templates: `source/templates/classic/partials/pagespeed.ejs`,
  `source/templates/repository/partials/pagespeed.ejs`, `source/templates/terminal/partials/pagespeed.ejs`.
  Any change to the returned shape (`url`, `detailed`, `scores`, `metrics`, `screenshot`) must be checked
  against all three.

### Common Patterns
- Plain `imports.axios.get` with the API key in the query string, no headers.
- `imports.format.error(error, {descriptions: {"429": "...", custom(error) {...}}})` is the repo pattern for
  turning provider-specific error bodies into a one-line message shown inside the rendered card.

## Dependencies
