# repositories

## Purpose
Renders repository cards (open graph image, description, language, stars, forks, issues, pull requests,
license, creation date) for a chosen set of repositories. Four independent sources feed the same list:
explicitly named `featured` handles, the account's `pinned` items, its most `starred` repositories, and a
`random` pick from its recent repositories. Results are de-duplicated across sources and then sorted by the
user-defined source order.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Sequentially runs the four sources into `repositories.list`, keeping a `processed` Set of `nameWithOwner` to avoid duplicates, then sorts by `order.indexOf(sorting)`. Module-level `format(repository, {sorting})` helper rewrites `createdAt` into a human string and tags the source. |
| `metadata.yml` | `category: github`, `index: 14`, `supports: user, organization`, `scopes: public_access`. Inputs: `featured`, `pinned` (0-6), `starred` (0-100), `random` (0-100), `order` (default `featured, pinned, starred, random`), `forks`, `affiliations` (owner/collaborator/organization_member, default `owner`). |
| `examples.yml` | Two examples: featured `lowlighter/metrics`, and two pinned repositories. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` `load.plugin` reads every file in it as a GraphQL query string.
  Contents:
  - `repository.graphql` (`query RepositoriesRepository`) - full card payload for one repository:
    `createdAt`, `description`, `forkCount`, `isFork`, `issues.totalCount`, `nameWithOwner`,
    `openGraphImageUrl`, `licenseInfo {nickname, spdxId, name}`, `pullRequests.totalCount`, `stargazerCount`
    and `primaryLanguage {color, name}`. Variables: `$owner`, `$name`.
  - `pinned.graphql` (`query RepositoriesPinned`) - `user(login).pinnedItems(types: REPOSITORY, first: $limit)`
    with the same fields inlined behind `... on Repository`. Variables: `$login`, `$limit` (always called with
    6, then sliced down to the requested count client-side).
  - `starred.graphql` (`query RepositoriesStarred`) - `user(login).repositories(orderBy STARGAZERS DESC,
    first: $limit, privacy: PUBLIC, ...)` returning `nameWithOwner` only. Variables: `$login`, `$limit`
    (`min(starred + 10, 100)`), `$affiliations` (a whole pre-rendered `ownerAffiliations: [...]` argument or
    empty), `$forks` (the literal `isFork: false` or empty).
  - `random.graphql` (`query RepositoriesRandom`) - same shape but `orderBy UPDATED_AT DESC, first: 100`, with
    the shuffling done client-side. Variables: `$login`, `$affiliations`, `$forks`.

## For AI Agents
### Working In This Directory
- `starred` and `random` are two-phase: a cheap query returns `nameWithOwner` only, then each surviving entry
  costs one extra `repository` query for the card fields. Requesting 100 starred repositories therefore means
  roughly 101 GraphQL calls.
- `featured` handles are parsed as an optional `owner/` prefix plus a name; without a prefix the owner
  defaults to the current `login`.
- `affiliations` and `forks` are interpolated as complete GraphQL arguments, not values. An empty
  `plugin_repositories_affiliations` produces an empty string and therefore no `ownerAffiliations` argument
  at all, which is how "fetch everything" is expressed.
- Despite `supports: user, organization` in `metadata.yml`, the `pinned`, `starred` and `random` queries
  hardcode `user(login: "$login")`. On an organization account those three return a null `user` and the
  destructuring throws, so in practice only `featured` works for organizations. Fix would require
  `$account`-polymorphic queries as used by the `people` and `projects` plugins.
- `pinned` always requests the maximum of 6 and slices afterwards, so lowering the input does not save a call.
- Sorting is by source, not by any repository property. `order` values not present in the list are simply
  never matched, and `indexOf` returns -1 for an unknown `sorting`, placing it first.

### Testing Requirements
- `tests/cases/repositories.plugin.yml`, via `npm run test-metrics`.
- GraphQL mocks: `tests/mocks/api/github/graphql/repositories.repository.mjs`, `repositories.pinned.mjs`,
  `repositories.starred.mjs`, `repositories.random.mjs`, matched against the `RepositoriesRepository`,
  `RepositoriesPinned`, `RepositoriesStarred` and `RepositoriesRandom` operation names.
- Rendered by `source/templates/classic/partials/repositories.ejs` only. As the metadata notes, the cards
  cannot be clickable because the output is embedded through an `<img>` tag.

### Common Patterns
- De-duplication with a `Set` of `nameWithOwner` shared across every source.
- A module-level `format()` helper rather than inline mapping, so all four sources produce identical objects.
- Relative date formatting inline: under one day becomes "N hours ago", under 30 days "N days ago",
  otherwise `new Date(...).toDateString().substring(4)`.
