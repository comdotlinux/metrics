# lines

## Purpose
Lines-of-code plugin: sums lines added, deleted and changed across the account's repositories using the GitHub REST
contributor statistics endpoint, and can draw a d3 area chart of that diff over time. `supports: user, organization,
repository`, `scopes: public_access`, `category: github`, `index: 3`. There is **no `queries/` directory**; the plugin is
REST-only and reuses the repository list already fetched by the base query.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Picks a mode (`organization` when `data.account` is set, `repository` when `q.repo` is set, otherwise `user`), then calls `rest.repos.getContributorsStats({owner, repo})` for every non-skipped repository under `Promise.allSettled`. In user mode it keeps only the contributor whose login matches; in organization and repository mode it keeps all contributors. Each contributor's weekly `{a, d, c, w}` tuples are summed per repository and also bucketed per ISO week date into a global `weeks` map. Returns totals, a `repos` list sorted by total churn and sliced to `repositories.limit`, the `weeks` series, and optionally `history` (an SVG string). |
| `index.mjs` history block | Builds a 480x315 SVG with `imports.D3node` + `imports.d3`: a time x-axis (labels rotated -45 degrees), a symmetric linear y-axis over `[+extremum, -extremum]` with `.2s` tick formatting, and two mirrored `d3.area()` paths - additions in `rgb(63, 185, 80)` above the origin, deletions in `rgb(218, 54, 51)` below it. Each series plots `added + changed` / `-(deleted + changed)`. Sets `result.history = null` when no week survives the year filter. |
| `metadata.yml` | `plugin_lines`, `_skipped` (inherits `repositories_skipped`), `_sections` (`base`/`repositories`/`history`, default `base`; `base` needs the base plugin's `repositories` section), `_repositories_limit` (4), `_history_limit` (years back, default 1, `zero: disable`), `_delay` (seconds, default 0, `zero: disable`). |
| `examples.yml` | Two examples, both using `plugin_lines_delay: 30`; the second adds `sections: repositories, history` and a `repositories_skipped` pattern list. |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## For AI Agents
### Working In This Directory
- **`plugin_lines_delay` exists because `getContributorsStats` is lazily computed by GitHub.** The first call can return
  cached or incomplete data (the endpoint answers `202` while it builds the statistics). When `delay` is non-zero the
  whole fetch loop runs twice with a `setTimeout` pause in between, and only the second response is used. Weird or zero
  totals are the symptom this option addresses.
- The per-repository guard is `Array.isArray(stats)`, so any non-array body - what the endpoint returns while it is
  still computing statistics - is silently dropped rather than raising.
- `a` / `d` / `c` / `w` in the API payload are added, deleted, changed and the week timestamp in seconds. `changed` is
  added to **both** the addition and deletion series in the chart, which is why the two halves are not mirror images of
  the raw `added` / `deleted` totals.
- `history.limit` filters by calendar year (`new Date(new Date().getFullYear() - limit, 0, 0)`), not by a rolling window,
  so `1` means "since the start of last year".
- The repositories list is sorted by `updatedAt`, but `updatedAt` is not among the fields projected into the mapped
  objects, so that sort is effectively a no-op today. Do not rely on the ordering of `repositories` before the churn sort.
- The repository-mode debug line says `... > people > switched to repository mode`; a copy-paste from the `people`
  plugin, also present in `introduction` and `languages`.

### Testing Requirements
- `npx jest --runInBand metrics.test.js -t Lines` runs `tests/cases/lines.plugin.yml`.
- Mock: `tests/mocks/api/github/rest/repos/getContributorsStats.mjs`. No GraphQL mock is involved.
- Templates rendering it: `source/templates/classic/partials/lines.ejs`, `source/templates/repository/partials/lines.ejs`,
  `source/templates/terminal/partials/lines.ejs`. The `base` section renders inside the base plugin's repositories block,
  so `base: repositories` must be set for it to appear.

### Common Patterns
- `Promise.allSettled` + `.filter(({status}) => status === "fulfilled")` so one inaccessible repository does not fail the
  plugin, the same shape as `habits`.
- `imports.D3node` / `imports.d3` come from `source/app/metrics/utils.mjs`; the SVG is serialized with `d3n.svgString()`
  and embedded as a string, the same approach used by the `Graph` helpers.
- Standard enable guard and `try {} catch (error) { throw imports.format.error(error) }`.

## Dependencies
