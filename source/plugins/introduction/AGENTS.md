# introduction

## Purpose
Introduction plugin: renders a single free-text blurb, picked from whichever entity is being rendered - a user's `bio`,
an organization's `description`, or a repository's `description`. `metadata.yml` notes it is "mostly intended for
external usage", since a bio is already shown on the GitHub profile page. `supports: user, organization, repository`,
`scopes: public_access`, `category: github`, `index: 26`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Picks a mode: `account` by default, or `"repository"` when `q.repo` is set (owner/repo are then taken from the first node of `data.user.repositories.nodes`). Dispatches with `queries.introduction[context.mode](context)` and reads the response field through a lookup table `{user: "bio", organization: "description", repository: "description"}`. Returns `{mode, title, text}`. |
| `metadata.yml` | `plugin_introduction` and `plugin_introduction_title` (boolean, default `yes`, controls whether the section heading is drawn). |
| `examples.yml` | Two examples: an organization one (`user: github`, `base: header`, overridden in `prod` to use `METRICS_TOKEN_WITH_SCOPES`) and a repository one (`template: repository`, `repo: metrics`). |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` loads every file there as a GraphQL query string. Contents (one file per mode,
  file names are load-bearing because `index.mjs` indexes them by `context.mode`):
  - `user.graphql` (op `IntroductionUser`, vars: `$login`) - `user(login).bio`.
  - `organization.graphql` (op `IntroductionOrganization`, vars: `$login`) - `organization(login).description`.
  - `repository.graphql` (op `IntroductionRepository`, vars: `$owner`, `$repo`) - `repository(name, owner).description`.

## For AI Agents
### Working In This Directory
- The `queries/` file names are the dispatch keys. Renaming `user.graphql` breaks user mode at runtime with an
  undefined-is-not-a-function error, not a load-time error.
- The extra context keys (`mode`, `login`) are harmless: `$login` is unused by `repository.graphql`, and unused
  substitutions are simply not applied.
- The repository-mode debug line reads `... > people > switched to repository mode`. That `people` is a copy-paste from
  the `people` plugin and is present in `languages` and `lines` too. It is cosmetic; leave or fix consistently.
- Only three fields are ever fetched, so this plugin is cheap. Do not extend it into a general profile plugin; `base`
  already covers profile data.

- Standard enable guard, `inputs({data, account, q})`, and `try {} catch (error) { throw imports.format.error(error) }`.
