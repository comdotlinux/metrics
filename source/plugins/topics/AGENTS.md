# topics

## Purpose
The `topics` plugin (`📌 Starred topics`, category `github`, index 4) displays the GitHub topics an
account has starred. Starred topics have no API, so it drives puppeteer over
`https://github.com/stars/<login>/topics` and scrapes the result list. It renders either as text labels
or as the topics' artwork icons. Supports `user` only, needs no GitHub scopes, and declares the
`metrics.run.puppeteer.scrapping` extra.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Maps `mode` through `{starred: "labels", labels: "labels", mastered: "icons", icons: "icons"}` into `type`, treats `sort === "random"` as a shuffle flag and otherwise passes `sort` straight into the URL query. Loops pages 1 to 100 loading `?direction=desc&page=<i>&sort=<sort>`, races `frame.waitForSelector("ul.repo-list")` against `frame.waitForSelector(".blankslate")`, then scrapes each `ul.repo-list li` for `.f3` name, `.f5` description, `img` icon src and the first anchor href. Breaks as soon as a page yields zero entries. After closing the browser it optionally shuffles, applies the label-mode limit (appending a synthetic `And N more...` entry whose description lists the dropped topic names), base64-encodes each icon twice via `imports.imgb64` (once natural, once forced to 24x24 as `icon24`), HTML-escapes descriptions, and finally applies the icon-mode limit after dropping topics that have no icon. Returns `{mode, type, list}`. |
| `metadata.yml` | Inputs `plugin_topics` (extras `metrics.run.puppeteer.scrapping`), `plugin_topics_mode` (`labels`, `icons`, `starred` alias of labels, `mastered` alias of icons; default `starred`), `plugin_topics_sort` (`stars`, `activity`, `starred`, `random`; default `stars`), `plugin_topics_limit` (0-20, default 15, `zero: disable`). |
| `examples.yml` | Two examples with `token: NOT_NEEDED`: `metrics.plugin.topics.svg` (labels, limit 12) and `metrics.plugin.topics.icons.svg` (`mode: icons`, limit 0). |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- The two limits are applied at different points on purpose: in `labels` mode the limit runs before icon loading (so only visible icons are fetched, plus the `And N more...` summary), while in `icons` mode it runs after, because topics without artwork are filtered out first and would otherwise eat the quota.
- `sort: random` never reaches the URL; the page is fetched with `sort=random` literally, which GitHub ignores, and the shuffle happens locally through `imports.shuffle`. Output is therefore non-deterministic.
- `waitForSelector(".blankslate")` is the empty-state escape hatch. Without racing it, an account with no starred topics would hang until the puppeteer default timeout.
- Selectors `.f3`, `.f5` and `ul.repo-list` are Primer utility classes on a page GitHub can restyle at any time. A markup change yields an empty list rather than an error.
- The 100-page cap is hardcoded; the loop normally exits far earlier on the zero-results break.
- Descriptions are escaped with `imports.htmlescape` because they are injected into the SVG's inline HTML.

### Testing Requirements
- Test case: `tests/cases/topics.plugin.yml`, two cases with `use_mocked_data: yes` and `verify: yes`.
- There is no mock for this plugin: `tests/mocks/index.mjs` proxies graphql, rest, axios, rss and google-maps but not puppeteer, so these cases scrape the real github.com even in mocked mode and depend on the test account having starred topics.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_topics: yes`.

### Common Patterns
- `Promise.race` between a success selector and an empty-state selector to bound scraping latency.
- Two-resolution image encoding (`icon` and `icon24`) so templates can pick without re-fetching.
- A synthetic overflow entry (`And N more...`) instead of silently truncating, so the rendered card stays informative.
