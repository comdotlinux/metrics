# support

## Purpose
The `support` plugin (`💭 GitHub Community Support`, category `github`, no `index` key) scraped a
`github.community` Discourse profile for forum statistics (accepted solutions, posts created, topics
created, likes received) and badge counts. `metadata.yml` carries a `deprecation` notice: GitHub Support
Community moved to GitHub Discussions in July 2022 and `github.community` no longer serves those pages,
so this plugin is effectively dead. Supports `user` only, no GitHub scopes, declares the
`metrics.run.puppeteer.scrapping` extra.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Launches `imports.puppeteer.launch()` and visits three pages in sequence: `https://github.community/u/<login>` to confirm the account exists by waiting up to 5 s for `.user-profile-names` (otherwise throws `Account does not exists on github.community`), then `/summary` waiting for `.stats-section` and mapping each `li` label/value pair through a regex switch (`/solutions?/`, `/posts? created/`, `/topics? created/`, `/received/`) into `result.stats`, then `/badges` waiting for `.badge-group-list` and collecting `.badge-card .badge-link` names plus `.grant-count` numbers. Badge count is `uniques.length + (sum(multiples) - multiples.length)`. Closes the browser and returns `{stats, badges}`. |
| `metadata.yml` | Single input `plugin_support` (boolean, extras `metrics.run.puppeteer.scrapping`). Contains the `deprecation` block pointing at the GitHub Discussions migration announcement. |
| `examples.yml` | One example `metrics.plugin.support.svg` with both `prod.skip: true` and `test.skip: true`, so it is neither published nor tested. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- Known bug: `index.mjs` calls `imports.metadata.plugins.stackoverflow.inputs({data, account, q})` instead of `...plugins.support.inputs(...)`. The result is discarded so it has no visible effect today, but it is a copy-paste leftover and will throw if the `stackoverflow` plugin is ever removed or renamed.
- `result.stats` is initialized with a `received` key, but the regex branch for `/received/` writes `hearts`. Both keys therefore appear in the output, `received` always 0.
- The plugin targets a Discourse instance that has been retired. Do not spend effort repairing selectors; if this needs to live on, the replacement data source is the GitHub Discussions GraphQL API, which would make it a different plugin entirely.
- Any `metadata.yml` change still needs `npm run build`, which regenerates `README.md`, `action.yml`, `settings.example.json` and `tests/cases/support.plugin.yml`.

### Testing Requirements
- `tests/cases/support.plugin.yml` is an empty list (`[]`) because the single example sets `test.skip: true`. Nothing in the jest suite exercises this plugin.
- There is no mock: puppeteer is not proxied by `tests/mocks/index.mjs`, so any run would hit the real (now dead) `github.community`.
- To try it manually: `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes` with `plugin_support: yes`. Expect the existence check to throw.

### Common Patterns
- `frame.waitForSelector(selector, {timeout})` wrapped in `try/catch` as an existence probe.
- Label/value scraping normalized to lowercase then routed through a `switch (true)` regex dispatch, tolerating singular and plural wording.
- `.filter(kv => kv)` after a mapping that returns `null` for unrecognized labels, so unknown stats are dropped rather than crashing `Object.fromEntries`.

## Dependencies
