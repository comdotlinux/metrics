# stars

## Purpose
The `stars` plugin (`🌟 Recently starred repositories`, category `github`, index 5) lists the
repositories the account starred most recently, with their description, language, license, star and fork
counts, open issue and pull request totals, social preview image, and a humanized "starred X ago" label.
Supports `user` only; scope `public_access`. It is one of the smallest plugins in the repo: a single
GraphQL call plus date formatting.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Reads `limit`, runs `queries.stars({login, limit})` once (no pagination), then for each edge computes `time` in days since `starredAt` and writes `edge.starred` as `"N hours ago"` under a day, `"N days ago"` under 30 days, and otherwise `new Date(starredAt).toDateString().substring(4)` (for example `Mar 07 2024`). Returns `{repositories}` where `repositories` is the raw `edges` array with that extra field. |
| `metadata.yml` | Inputs `plugin_stars` and `plugin_stars_limit` (1-100, default 4). |
| `examples.yml` | One example producing `metrics.plugin.stars.svg` with `plugin_stars_limit: 3`. |
| `README.md` | Generated by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- `$limit` is substituted textually straight into `first: $limit`, so the `min`/`max` bounds in `metadata.yml` are the only thing keeping the GraphQL request valid. GitHub caps `first` at 100, which is why `max: 100`.
- The query hardcodes `user(login: ...)`, not `$account`, which is why `supports` lists `user` only.
- `openGraphImageUrl` is returned as a URL, not base64; unlike most plugins this one does not call `imports.imgb64`, so the template receives a remote URL.
- The plugin mutates the GraphQL response objects in place (`edge.starred = updated`) and returns them directly, so template code sees the raw GitHub field names (`nameWithOwner`, `stargazerCount`, `licenseInfo`).
- Any `metadata.yml` change needs `npm run build` to regenerate `README.md`, `action.yml`, `settings.example.json` and `tests/cases/stars.plugin.yml`.

### Testing Requirements
- Test case: `tests/cases/stars.plugin.yml`, generated from `examples.yml`.
- Mock: `tests/mocks/api/github/graphql/stars.default.mjs` backs `query StarsDefault`. `tests/mocks/index.mjs` camel-cases the mock file name to build the `^query StarsDefault ` matcher, so renaming the query in the `.graphql` file silently unmocks the plugin.
- Commands: `npm run test-metrics`, or `INPUT_USE_MOCKED_DATA=yes INPUT_TOKEN=MOCKED_TOKEN INPUT_DRYRUN=yes`.

### Common Patterns
- Single-shot GraphQL, no cursor loop: the display limit is small enough to fit one page.
- Relative-time humanization done in the plugin rather than the template, so all templates share the same wording.
