# code

## Purpose
Picks one random diff hunk from the account's recent push events and renders it as a syntax-highlighted code
snippet. It reuses the same REST events feed as the `activity` plugin, keeps only `PushEvent`s, fetches each
referenced commit, flattens the commits into per-file patches, discards patches longer than
`plugin_code_lines`, detects each file's language, then selects one at random and formats it. There is no
`queries/` directory; everything is REST plus local formatting.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | The whole plugin. Pages `rest.activity.listEventsForAuthenticatedUser` (or `rest.activity.listRepoEvents` when `q.repo` is set), then `rest.request(commit.url)` per commit. Keeps only commits with at most one parent (no merges) whose author login, email or name matches one of `data.shared["commits.authoring"]`. Trims the common indentation off the patch, escapes it with `imports.htmlescape`, runs `imports.highlight(content, "diff")`, unescapes, converts newlines to `<br/>` and replaces the blank diff prefix span with a middle dot so unchanged lines stay visible. |
| `metadata.yml` | `category: github`, `index: 23`, `supports: user, organization`, `scopes: public_access`. Inputs: `plugin_code`, `plugin_code_lines` (1-128, default 12), `plugin_code_load` (100-1000 events, default 400), `plugin_code_days` (0-365, default 3, `0` disables the age filter), `plugin_code_visibility` (`public|all`, default `public`), `plugin_code_skipped` (`inherits: repositories_skipped`), `plugin_code_languages` (allowlist). Carries a `notes:` warning that a misconfigured instance can leak private code. |
| `examples.yml` | One example limited to `javascript, typescript` with `plugin_code_load: 400`. |
| `README.md` | GENERATED by `npm run build`. Never hand-edit. |

## For AI Agents
### Working In This Directory
- This plugin reads commit contents, so treat `plugin_code_visibility: all` as a privacy decision, not a
  display option: with a `repo`-scoped token it will happily surface private diffs. The `notes:` block in
  `metadata.yml` is the user-facing warning and should stay.
- The authorship filter is `data.shared["commits.authoring"]` (from `base`, defaulting to `.user.login`)
  matched case-insensitively as a substring against the commit author's `login`, `email` and `name`. If a
  snippet never appears for a real account, that list is usually why.
- `PushEvent` payloads no longer always carry a `commits` array, so the flatMap is `(payload.commits ?? [])`
  (the same guard upstream PR 1834 added to `activity` and `habits`; this plugin and
  `source/plugins/languages/analyzer/recent.mjs` were the two remaining unguarded consumers).
- Commit fetching is one `rest.request(commit.url)` per commit in every push event of every page, so
  `plugin_code_load` is expensive; the default of 400 is already 4 pages of events plus one request per commit.
- `imports.language({filename, patch, prefix: login})` runs `linguist-js` over the patch content and returns a
  lower-cased language name, `"unknown"` when it cannot decide (the `prefix` property is ignored by the helper
  signature); `plugin_code_languages` then filters on that result.
- The indent trimming only fires when the first patch line does not already end with `@@`; otherwise the hunk
  header is truncated to just the `@@ ... @@` coordinates. Both branches assume a unified diff.
- Returning `{snippet: null}` is a normal outcome when no candidate file survives the filters; the partial is
  expected to handle it.

### Testing Requirements
- `npm run test-metrics` runs `tests/cases/code.plugin.yml` for `classic` only (`code.ejs` exists only in
  `source/templates/classic/partials/`, and `supports:` excludes `repository`).
- Mocks: `tests/mocks/api/github/rest/activity/listEventsForAuthenticatedUser.mjs` and `listRepoEvents.mjs`
  supply the push events, and `tests/mocks/api/github/rest/request.mjs` answers the per-commit fetch. That mock
  only matches `https://api.github.com/repos/lowlighter/metrics/commits/MOCKED_SHA`, so the mocked push events
  must keep using `MOCKED_SHA` commit URLs for this plugin to produce a snippet under `use_mocked_data`.
- Rendered by `source/templates/classic/partials/code.ejs`.

### Common Patterns
- Result shape: `{snippet: {created, sha, message, filename, status, additions, deletions, patch, repo, language} | null}`.
- The event pipeline is a chain of `.filter(...)` calls followed by `.flatMap(...)` into per-commit promises,
  all inside one `await Promise.all([...])`.
- Random selection is `files[Math.floor(Math.random() * files.length)] ?? null`, which is why repeated renders
  intentionally differ.
