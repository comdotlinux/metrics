# followup

## Purpose
Follow-up plugin: reports open/closed issue ratios and open/closed/merged pull request ratios, either for the
repositories owned by the account (`repositories` section, read from already-computed data) or for issues and PRs the
user opened anywhere on GitHub (`user` section, one GraphQL `search` call). An opt-in `indepth` mode additionally runs
eight extra `search` queries per repository to separate community contributions from collaborator ones.
`supports: user, organization, repository`, `scopes: public_access`, `category: github`, `index: 9`.

## Key Files
| File | Description |
|------|-------------|
| `index.mjs` | Builds a `followup` object whose `issues.open/closed` and `pr.open/closed/merged` are **getters over `computed.repositories.*`** (no API call for the default section). Indepth mode loops `data.user.repositories.nodes`, fetches push-access collaborators, turns them into `-author:<login>` exclusions and runs `queries.followup.repository`, aggregating per-repo results into `followup.<section>.collaborators.<type>`. The `user` section runs only when `account === "user"` and `sections` contains `user`. |
| `metadata.yml` | `plugin_followup`, `plugin_followup_sections` (array `repositories`/`user`, default `repositories`), `plugin_followup_indepth` (boolean, `extras: metrics.api.github.overuse`), `plugin_followup_archived` (boolean, default `yes`). |
| `examples.yml` | Four examples: default, `sections: user`, `indepth: yes`, and `archived: no` (the last is `prod: skip: true`, so it is not published to the examples branch). |
| `README.md` | Generated by `npm run build`. Do not hand-edit. |

## Skipped subdirectories
- `queries/` - no AGENTS.md: `setup.mjs` registers every file in it as a GraphQL query string. Contents:
  - `user.graphql` (op `FollowupUser`, vars: `$login`, `$archived`) - eight aliased `search(type: ISSUE, first: 0)` calls returning only `issueCount`: `issues_open`, `issues_drafts`, `issues_skipped` (`is:closed label:wontfix,duplicate`), `issues_closed`, `pr_open`, `pr_drafts`, `pr_closed` (`is:unmerged is:closed draft:false`), `pr_merged`. `$archived` is substituted with the literal `archived:false` qualifier or an empty string.
  - `repository.graphql` (op `FollowupRepository`, vars: `$owner`, `$repo`, `$collaborators`) - the same eight aliases scoped with `repo:$owner/$repo`; `$collaborators` expands to a space-separated list of `-author:<login>` exclusions.
  - `repository.collaborators.graphql` (op `FollowupRepositoryCollaborators`, vars: `$owner`, `$repo`) - `repository.collaborators.nodes.login`, i.e. users with push access.

## For AI Agents
### Working In This Directory
- `archived` is a boolean input but reaches the query as a search qualifier string: `archived === false ? "archived:false" : ""`.
  It is only wired into `user.graphql`; the repository-scoped query ignores it.
- The collaborators query needs a token with push access; a failure is swallowed by
  `.catch(() => ({repository: {collaborators: {nodes: [{login: owner}]}}}))`, which falls back to just the repo owner. Any
  other indepth error is caught per repository and only logged, so partial results are normal.
- `issues.drafts`, `issues.skipped` and `pr.drafts` at the top level stay `0` for the `repositories` section; indepth
  counts land in `followup.issues.collaborators.*` / `followup.pr.collaborators.*` instead. The `count` getters therefore
  add zeros there.
- Indepth mode is gated twice: the input must be `yes` **and** `imports.metadata.plugins.followup.extras("indepth", {extras})`
  must pass, which on web instances requires `metrics.api.github.overuse` in the instance `extras` settings.
- Changing options requires `npm run build` to regenerate `README.md`, `action.yml`, `settings.example.json` and
  `tests/cases/followup.plugin.yml`.

### Common Patterns
- Lazy getters (`get count() { return this.open + ... }`) so totals stay correct after indepth mutation.
- Result keys are decoded with `const [section, type] = key.split("_")`, which is why every alias must stay
  `<issues|pr>_<type>`; renaming an alias silently misroutes its count.
- Standard enable guard + `try {} catch (error) { throw imports.format.error(error) }`.
